## 1. 安装与卸载

### 安装

```bash
# 开发态：从本地目录安装
dsh plugin --profile web add D:\path\to\dsh-buddy-expert-hub

# 正式：从 npm 安装
dsh plugin --profile web add dsh-buddy-expert-hub
```

安装后**重启 / 刷新 dsh web**，左侧边栏出现「专家·技能·连接器」图标即表示加载成功。

> 连接器的「连接」阶段会写入宿主 `cordis.patch.yml`，**写入后需要重启 dsh web** 才生效；插件无法重启自己所在的宿主进程。

### 卸载

```bash
dsh plugin --profile web remove dsh-buddy-expert-hub
```

卸载**不会**删除数据：`~/.dsh/ntd-resource`、`~/.dsh/dsh-buddy-expert-hub/`、`~/.dsh/experts/`、`~/.dsh/skills/` 都会保留。需要彻底清理时手动删除对应目录（删之前请先备份自己导入的专家和技能）。

## 2. 界面总览

点左侧栏「专家·技能·连接器」进入面板：

| 区域 | 作用 |
| --- | --- |
| 顶部四个标签页 | 专家 / 专家团 / 技能 / 连接器，徽标显示各自总数 |
| 工具栏左侧 | 「全部 / 已安装 / 云端」三视图按钮 |
| 工具栏右侧 | 一个 `+` 按钮，四个页各自含义不同（见第 4 节） |
| 搜索框 | 250ms 防抖；**每个标签页各保留自己的关键词** |
| 卡片 / 列表行 | 点击后右侧滑出详情抽屉，窄屏自动全屏；`Esc`、右上 ✕、点遮罩都能关 |
| 右上「刷新」 | 触发一次资源仓库同步；数据源是本机目录时改为重读目录，不联网 |

### 三视图的语义

| 视图 | 含义 |
| --- | --- |
| 全部 | 当前列表全量 |
| 已安装 | 本机已导入 / 已安装的条目 |
| 云端 | **按资源类型区分**：专家 / 专家团 = 资源仓库来源（排除本地导入）；技能 = **SkillHub 云端商店**；连接器 = `origin=cloud` |

补充：

- 技能页有两个子分组「仓库技能 / SkillHub 商店」，与工具栏视图**双向同步**：点子分组会切视图，点视图也会高亮子分组，不会出现两个视图渲染同一个列表。
- 连接器的「已安装」视图下多一行来源筛选：**全部 / 本地自定义 / 云端下载**，可继续细分。
- 空态会按当前视图给出下一步动作；「已安装」为空时引导点对应 `+` 按钮。
- 四个页的工具栏由同一个组件渲染，位置、样式、按钮顺序完全一致；`+` 按钮没有 `title` 悬浮提示，只有 `aria-label`。

### 列表细节

- 专家 / 专家团详情底部有「导入」按钮，导入后变成「已导入 ✓」并禁用；详情右上「导出」可生成单条目包。
- 已导入的专家在列表**置顶**，卡片带「本地」标识。
- 技能列表每页 60 条，滚动到底部或点「加载更多」继续加载。

## 3. 四个标签页怎么用

### 专家 / 专家团

浏览资源仓库里的条目 → 点卡片看详情（正文截断 2000 字）→ 点「导入」。

导入会把条目转换成 **dsh 原生专家格式**落到 `~/.dsh/experts/<id>/`，导入后即可在输入框的专家按钮里选用。同 id 已存在时不会覆盖，返回「已导入」。

### 技能

三个来源：

| 来源 | 说明 | 怎么用 |
| --- | --- | --- |
| 仓库技能 | 资源仓库 `skills/<集合>/.../SKILL.md` | 点卡片 `+` 或「添加技能」安装到 `~/.dsh/skills/` |
| SkillHub 商店 | 云端商店，切到「云端」视图 | 按分类浏览、搜索、安装；商店地址可在设置里改 |
| 内置技能 | 插件包自带，见第 8 节 | 设置里一个开关，装完在列表里不可见 |

技能引用要求**已安装且开启**：未安装会提示先点 `+`；已关闭会提示到「已安装」里开启，不再生成降级指令名。

#### 中文名、版本号与图标

资源仓库的技能目录里可能带两个可选文件，插件会自动识别，不需要你做任何配置：

| 文件 | 效果 |
| --- | --- |
| `_skillhub_meta.json` | `name`（中文名）替换列表 / 详情 / 选择器里显示的名称；`version` 在名称右侧显示 `vX.Y.Z` 徽标 |
| `_icon.png` / `.jpg` / `.svg` | 作为技能图标；没有或加载失败时回落到原来的彩色首字母方块 |

四处展示统一：技能列表卡、详情头图与「版本」统计、输入框专家按钮的选择器、「已安装」列表。搜索框也支持用中文名搜技能。

**不改变的东西**：`SKILL.md` 里的机器名、`/` 指令名、安装后的落地目录名都保持原样；装进 `~/.dsh/skills/` 时这两个文件会一起复制过去，所以已安装列表同样显示中文名、版本和图标。

> 维护者提示：资源仓库里部分目录带历史后缀 `__skillhub`（如 `academic-figures__skillhub`）。可用 `node scripts/strip-skillhub-suffix.mjs --root <skills 目录> [--apply]` 去掉（默认预演，`--apply` 才执行）。脚本**只改目录名、不改任何文件内容**，且插件对改名前后的 id 都做了兼容，旧草稿里的引用不会失效。详见 `README.md`。

## 4. 文件夹导入（+ 按钮）

专家 / 专家团 / 技能三个标签页的 `+` 按钮打开同一个「文件夹导入」弹窗，只是类型不同；连接器的 `+` 是手填 MCP 配置的表单，不走文件夹导入：

| 标签页 | 按钮 | 类型 |
| --- | --- | --- |
| 专家 | 导入专家 | `expert` |
| 专家团 | 导入专家团 | `team` |
| 技能 | 添加技能 | `skill` |
| 连接器 | 新增连接器 | 弹窗里手填 MCP 配置（不走文件夹导入） |

### 各类目录必需的校验文件

| 类型 | 目录根下必需 | 可选 / 兼容 |
| --- | --- | --- |
| 技能 | `SKILL.md`（frontmatter 建议写 `name`，解析不出用目录名兜底） | `README.md` 及其它资源 |
| 专家 | `expert.yml`（至少 `id` / `display_name`）+ `role.md` | 或 `.codebuddy-plugin/plugin.json`（含 `name` / `displayName`），按兼容格式转换 |
| 专家团 | `expert.yml` + `role.md` + `team.json`（含 `teamInfo` 或 `members`） | 或 `plugin.json` 带团队信息（`expertType=team`），导入时生成 `team.json` |

校验失败会**逐条列出缺哪些文件**，后端是权威校验方，前端只做同规则轻量预检。

### 两种模式

1. **单条目**：先把所选目录整体当一个条目校验，通过就只导入这一个；
2. **批量**：整体校验不通过时，把**一级子目录**各当一个条目分别校验（只看第一层，不递归），成功的导入、失败的逐条列出中文原因；全部失败时给出汇总（如「3 个子目录均校验失败」）。

### 限制与落盘位置

- 单文件 ≤ 2MB、最多 200 个文件、解码后总计 ≤ 20MB（前后端双重限制）；
- 已知文本扩展名按 UTF-8 读，图片等二进制按 base64；
- 拒绝 `..`、绝对路径、Windows 盘符、反斜杠路径、符号链接；
- 技能落 `~/.dsh/skills/<净化后的名字>/`，专家 / 专家团落 `~/.dsh/experts/<id>/`；
- **绝不覆盖已存在目录**：同名返回 `already: true`，你手工改过的内容原样不动。

## 5. 在对话里使用：专家按钮与 `/`

### 专家按钮（输入框工具栏）

点击后弹出的二级列表**只列本机已安装的条目**（服务端按 `installed=1` 过滤）：

| 分类 | 列入条件 |
| --- | --- |
| 专家 / 专家团 | 本地已导入的条目 |
| 技能 | `~/.dsh/skills/` 里真实存在的技能（含已关闭的，选中时提示「已关闭」）；**内置开关装的那一批不列** |
| 连接器 | 本地已定义 / 已安装的连接器 |

某一类一条都没有时，会给出中文说明和一个「打开面板安装」按钮，直接跳到侧栏面板。

> **换专家就在当前对话里换，chip 会立刻更新。** 之前试过「一个会话只注入一次、第二次强制新建会话」，但宿主只能 `create` 会话、没有自动切换当前会话的能力，新建的会话不会变成你正在看的那个，结果就是「选了专家却看不到 chip」。现已改回：删除或直接换专家时，插件移除旧专家注入的设定、再在当前会话注入新专家，输入框工具栏的常驻 chip 随之更新。针对「AI 还在按旧专家行事」的问题，注入的设定里会明确声明「本会话当前唯一有效身份」，要求忽略此前其它专家及其子智能体。面板里点专家卡片的「召唤」仍会另开新会话，不受影响。

> 面板四个 Tab 本身不受影响，仍是「全部 / 已安装 / 云端」三视图；`installed=1` 只作用于输入框选择器。

### `/` 技能指令

- 触发字符**只有 `/`**：输入 `/` 从「技能」分组里选已安装且开启的技能。
- **` @ ` 不再弹出连接器列表**。`@` 完全回归宿主原生的「文件或对话」候选；专家 / 专家团 / 技能 / 连接器这四类一律走专家按钮。
- 指令名取自 `/skills/installed` 返回的 `dir`（即 `SKILL.md` frontmatter `name` 净化后的宿主原生技能目录名），**不是**仓库里的相对路径 `skills/<集合>/<名字>`。
- 发送后用户消息里**只显示 `/技能名`**，不会把整篇 `SKILL.md` 塞进发送内容。宿主启动时会扫描 `~/.dsh/skills/<dir>/SKILL.md` 并按需加载，插件再内联一遍是重复且白白耗 token。
- 关闭态技能宿主扫描不到，自然也不会出现在 `/` 菜单里。

技能引用一共**三个入口**，发送后统一变成 `/技能名`、都不会内联正文：① 输入框 `/` 菜单（主路径）；② 列表页技能卡片的「引用」气泡；③ 工具栏的专家按钮里的「技能」分类。三者都会先查已安装记录，再插入结构化引用，由同一份 codec 展开。旧草稿里残留的旧格式引用会自动净化成合法指令名，不会报错。

> `/` 同时是宿主内置 slash-menu 的触发符。插件注册前会探测 `inputTriggers`；若被拒，先尝试 `/skill`，两者都失败会明确告警「宿主不允许 / 触发源」，**不会静默退回 `@` 菜单**。可在控制台用 `__expertHubDiag().skillTrigger` 查注册结果，`__expertHubDiag().atTrigger` 会写着 `@` 源已注销。

## 6. 连接器三步：发现 → 安装 → 连接

**安装只保存定义，连接才写宿主配置。** 这是最容易混淆的一点。

### 第 1 步：发现

| 来源 | 位置 | 卡片显示 |
| --- | --- | --- |
| 云端 | 资源仓库 `connectors/connectors.json`（单文件清单） | 未安装的显示 `+` 图标 |
| 本地 | `~/.dsh/dsh-buddy-expert-hub/connectors/<dir>/connector.json` | 「本地自定义」或「云端下载」来源徽标 |

同 id 时**本地定义优先**。云端清单里每一条都会进列表，连不了的显式标出来：`cli`、`sse`、地址含 `${VAR}` 占位符的条目标 `connectable: false`、置灰「不可连接」，不给安装 / 连接入口。

### 第 2 步：安装

- 云端卡片点 `+` → 把定义复制到本地 `connectors/<dir>/`；**不写 profile、不保存凭据**；
- 顶部「+ 新增连接器」可手填：名称、描述、传输方式（Streamable HTTP / stdio）、URL 或命令+参数+环境变量、请求头、必填参数名（留空则从 `${VAR}` 自动推断）；
- 已安装卡片显示 **× 卸载**：移除本地定义并断开连接登记，同时按具体 id 清掉所有会话里注入的上下文（`detachedSessions` 会回报清理了几个会话）。profile 里的条目不会自动删除。

### 第 3 步：连接

连接会把 `mcp-client` 配置片段写进宿主 `cordis.patch.yml`。写入后**需要重启 dsh web** 才生效。

> 地址含 `${VAR}` 占位符的条目在面板内没有任何连接入口（`/connectors/connect`、`/connectors/provision`、`/provision/preview` 都会 400），因为占位符不会被配置求值，写进去就是跑不起来的地址。要用这类连接器，需手动编辑宿主 `cordis.patch.yml` 把占位符换成真实值。

## 7. 设置详解

面板设置弹窗里共三类配置；其中「资源仓库地址」在填远程 git 地址时会多出一个分支子项。

### 7.1 资源仓库地址

默认远程资源仓库：`https://gitcode.com/zzx_2446/dsh-buddy-expert-hub-resource.git`

可以填两种：

| 类型 | 写法 | 行为 |
| --- | --- | --- |
| git 仓库 | `http://...`、`https://...` 或 `git@...`（不含空白 / `..`；`http://` 适用于内网自建 Git） | 配置分支后首次 `git clone --depth 1 --branch <分支>`，刷新执行 `git fetch --depth 1 origin <分支>` + `git reset --hard FETCH_HEAD`；未配置分支时不传分支参数，跟随远端 HEAD。分支可在设置里选，候选来自远端只读探测 |
| 本机目录 | **绝对路径** | 直接把这个目录当数据根读；不联网、不执行任何 git 命令，保存时校验目录结构，分支栏不显示 |

留空回到默认地址。**改成 git 地址是下次同步才生效**；切回 git 数据源时界面会提示「数据源已切换，点刷新以应用新数据源」，重启后仍会提示。

#### 7.1.1 资源仓库分支（仅 git 仓库）

地址填的是 `http://...` / `https://...` 或 `git@...` 时，设置弹窗会多出「资源仓库分支（可选）」一栏：

- 点「获取分支」从远端只读拉取分支列表（不克隆、不 checkout），选中即填入；私有仓库无权限或网络不可用时**仍可手动填写**分支名。
- 留空跟随**远端默认分支**（远端 HEAD）：此时 `clone` 不传 `--branch`、`fetch` 不指定 ref，由 git 自己决定检出哪个分支。默认资源仓库的远端 HEAD 是 `master` 而不是 `main`，所以这里不能写死 `main`。只接受纯分支名：字母、数字与 `.` `_` `-` `/`，不能以 `-` 或 `/` 开头，不接受 `refs/heads/...` 这类完整 ref，也不能含空格。
- 保存后**下次同步（点「刷新」）才生效**。只改分支、没改地址时同样会提示点刷新，因为索引内容可能随分支变化。
- 本机目录模式下这一栏不显示：该模式不执行任何 git 命令，也不会改动你目录里的工作树或当前分支。
- 若点「获取分支」提示「后端尚未加载新版本」：插件以 `link:` 方式装进 profile 时，后端 `lib/index.js` 只在 dsh 进程启动时 import 一次，**刷新浏览器只会更新前端资源**，必须重启 dsh web 进程才会加载新接口。此时仍可直接手动填写分支名，不影响保存。

数据根优先级：

1. 设置里配置的本机资源目录（需含 `experts/` / `skills/` / `connectors/` 至少其一）
2. 同步后缓存的 `~/.dsh/dsh-buddy-expert-hub/repo`
3. `~/.dsh/ntd-resource`（历史遗留的只读副本，通常只有 `experts/`）
4. 都没有 → 懒加载时自动克隆

> 如果只到第 3 级，专家立刻可用，但技能页会提示「技能数据尚未同步」并给「立即同步」按钮 —— 因为那份副本没有 `skills/`。

### 私有 Git 仓库（需要账号）

地址填的是远程 Git 仓库时，插件会用只读的匿名探测自动判断是不是私有仓库：需要账号才能访问时，设置弹窗多出「私有仓库凭据」一栏，填 **Git 用户名** 和 **访问令牌（PAT）** 即可。令牌用 AES-256-GCM 加密存在 `~/.dsh/dsh-buddy-expert-hub/credentials.enc`，不会写进 `state.json`、也不会回显；留空表示沿用已保存的令牌，点「清除」或「恢复默认」会删掉它。克隆、刷新、列分支时凭据走环境变量注入，不拼进 URL，也不会出现在命令行里。

> 内网 DNS 不通或探测超时时，插件**不会瞎猜**，可以手动勾选「这是私有仓库」来填写凭据。
> `git@` 开头的 SSH 地址用系统密钥，不需要在这里填账号。

### 7.2 SkillHub 地址

默认 `https://api.skillhub.cn`。可填内网镜像；留空或非法地址时回到默认值。分类结果缓存 10 分钟，请求超时 20 秒。

## 8. 内置技能开关（重点）

设置弹窗里的「**启用内置技能**」开关（`role="switch"` + 原生 checkbox）：

### 开启会做什么

把插件包内随包发布的内置技能全部装进 `~/.dsh/skills/`：

| 来源 | Windows | Linux |
| --- | --- | --- |
| `builtin/<平台>/skills/*` 独立技能包 | 4 | 16 |
| `builtin/<平台>/builtin-plugins/<插件>/skills/*` 里自包含的 | 0 | 0 |
| **合计可装** | **4** | **16** |

平台映射：`win32 → builtin/windows`，其它（linux / darwin）→ `builtin/linux`。目录不存在或为空时按 0 个处理，开关仍可点、不报错。

插件来源的技能要过**九条自包含规则**：依赖 `mcp__*` 工具、`ToolSearch` 发现的工具、`editor_sdk` 本地服务、`allowed-tools:` 限制、`../Xxx` 上级路径、插件根 `core/ agents/ hooks/ shared/ dist/ bin/ prebuilds/`、正文含 `Plugin`/`插件`、引用了不在本目录内的 `scripts/...`，命中任一即排除（原因可在 `excluded` 里看）。原因是这类技能复制出来会变成「列表里看得见、一调用就报工具不存在」。顶层独立技能包**不做文本筛查**。Windows 的插件来源技能已按可用性核查清空（原来能装但依赖 WorkBuddy 客户端能力的那批，以及永不被安装的死资源，都已删除）；`workbuddy-office-routing` 现在只把本地 Office 文件任务导向 `wps-office-suite`。

### 装完为什么在界面上看不到

**这是刻意设计**：内置技能在「已安装」列表、`/pick?installed=1`、输入框专家按钮里全部隐藏；宿主启动时仍会原生扫描 `~/.dsh/skills` 正常加载它们。想确认装没装，看 `GET /builtin/skills` 的 `counts.installed`，或看磁盘上有没有带 `.builtin-skill.json` 的目录。

### 关闭会做什么（重要）

关闭 = **真删**，不是移到禁用目录：

- 扫描 `~/.dsh/skills/` 与 `~/.dsh/skills-disabled/`，把**带 `.builtin-skill.json` 标记**的目录 `rmSync` 递归删除（不进回收站）；
- **没有标记的目录一律不动** —— 你自己装的、导入的、手写的技能，哪怕同名也保留；
- 返回 `removed:[dir]` 列出实际删掉的目录。

⚠️ **如果你手动改过某个内置技能里的文件，关闭会把改动一起删掉。** 想保留，先复制到别处，或删掉那个目录里的 `.builtin-skill.json`（去标记后插件就把它当用户技能，不再删也不再覆盖）。

### 其它行为

| 项 | 说明 |
| --- | --- |
| 不覆盖同名 | 目标目录已存在但无标记 → 跳过并记入 `skipped`：「同名技能已存在，未覆盖」，你的文件逐字节不动 |
| 幂等 | 重复开启 = 覆盖升级（计入 `updated`）；重复关闭 = 删 0 个 |
| 重名处理 | 顶层先占目录名，插件来源撞名追加 `-2`、`-3` |
| 标记文件 | 每个装进去的目录内写 `.builtin-skill.json`（`from / platform / sourceDir / origin / plugin / installedAt`），**只有带标记才会被移除** |
| 启动不自动装 | 只在用户显式点开关时触发；开启后目录被手动删了，再关一次或再开一次即可恢复 |
| 复制限制 | 单文件 ≤ 2MB / 单技能 ≤ 40MB / ≤ 400 文件 / 跳过符号链接；超限的技能整体失败并记入 `skipped`，不影响其它技能 |

### 与 WorkBuddy 的关系（最容易误解）

dsh 和 WorkBuddy 是**两套独立运行时**，各读各的目录：

| 目录 | 谁加载 |
| --- | --- |
| `~/.dsh/skills/` | dsh |
| `~/.workbuddy/skills/` | WorkBuddy 客户端 |
| `~/.workbuddy/plugins/`（45 个插件及其自带技能） | WorkBuddy 客户端 |

所以：

- **在 dsh 里看不到 WorkBuddy 装的技能是正常的**，不是 bug，也不是没同步；
- 本插件**不再读取 WorkBuddy 的任何目录或注册表**，宿主装没装插件都不影响这 4 个技能的安装（旧版本曾按「宿主已装就跳过」，该判定已删除）；
- 想在 dsh 里用某个 WorkBuddy 技能，只能让它**真的落进 `~/.dsh/skills/`**：用第 4 节的「添加技能」指向那个目录、从 SkillHub 装、或打开内置技能开关。注意：依赖该插件运行时（`mcp__*`、`editor_sdk`）的技能搬过去也调不起来。

## 10. 常见问题 FAQ

**Q1：装了插件但侧栏没有入口？**
确认 dsh 版本是 0.1.5-rc.1；安装后重启 / 刷新 dsh web；检查所用 profile 的 `package.json`（例如 `~/.dsh/profiles/desktop/package.json`）里 `dsh.profile.bundles` 是否包含 `dsh-buddy-expert-hub`，以及 `dependencies` 里是否有对应条目。

**Q2：技能页提示「技能数据尚未同步」？**
当前数据根是 `~/.dsh/ntd-resource` 这类只有 `experts/` 的副本。点「立即同步」或右上「刷新」从资源仓库拉完整数据；若设置里填的是本机目录，检查该目录下有没有 `skills/`。

**Q3：为什么在 dsh 里看不到 WorkBuddy 装的技能？**
两套运行时、两套目录，互不相通（见第 8 节末）。把技能装进 `~/.dsh/skills/` 才会出现在 dsh。

**Q4：打开「启用内置技能」后，列表里怎么一个都没多？**
内置技能在界面刻意隐藏。看 `GET /builtin/skills` 的 `counts.installed`，或看 `~/.dsh/skills/` 里带 `.builtin-skill.json` 的目录数。

**Q5：关闭内置技能会把我自己装的技能删掉吗？**
不会。只删带 `.builtin-skill.json` 标记的目录；无标记目录一律保留，同名也不动。但会**删掉你对内置技能做过的手工修改**。

**Q6：输入 `@` 怎么不弹连接器了？**
这是新版设计。`@` 回归宿主原生的文件 / 对话候选，连接器、专家、专家团、技能都从输入框的**专家按钮**里选。

**Q7：选中技能后发出去只有 `/技能名`，提示词没带上？**
正常。宿主会按需加载 `~/.dsh/skills/<dir>/SKILL.md`，插件不再内联整篇正文，省 token 也避免发送框里一大段提示词。若技能完全没生效，检查它是否已安装且开启、目录里有没有 `SKILL.md`。

**Q8：连接器装了但用不了？**
「安装」只保存定义，还要点「连接」写入宿主 `mcp-client` 配置，并且**重启 dsh web**。另外 `cli` / `sse` / 含 `${VAR}` 占位符地址的连接器会被标「不可连接」，需要手工改 `cordis.patch.yml`。

**Q9：导入文件夹时提示缺文件 / 校验失败？**
对照第 4 节的必需文件表。专家要 `expert.yml` + `role.md`，专家团再加 `team.json`，技能要 `SKILL.md`。批量模式只看一级子目录，不递归。

**Q10：导入 / 安装时提示「同名技能已存在，未覆盖」？**
插件绝不覆盖已有目录。想用新版本，先在「已安装」里删掉旧的（或改名），再重试。

**Q11：内置插件里那些看起来很有用的技能（tencent-docs、weixinpay 等）为什么没装？**
它们依赖所属插件的运行时（MCP 工具、editor_sdk 等），单独复制过来一调用就报工具不存在，所以被九条规则排除。补齐 `mcps/` 也没用 —— 本插件只复制 `SKILL.md`，不注册任何 MCP server。

**Q12：为什么有的技能显示中文名和版本号、有的没有？图标怎么有的有有的没有？**
看技能目录里有没有 `_skillhub_meta.json`（中文名 + 版本）和 `_icon.*`（图标），两项都是可选的，缺哪个就不显示哪个，回落原来的英文名 / 彩色首字母块。中文名只是展示，不影响 `/` 指令名和安装目录名。

**Q13：资源仓库目录名里的 `__skillhub` 后缀要管吗？**
不用管，插件对改名前后都能读。想统一命名可以跑维护脚本（见第 3 节），脚本只改目录名、不改任何文件内容；改完点一次「刷新」重建索引即可。

## 12. 个人工作台

「个人工作台」是左侧栏的独立面板：**左侧是文件树**（每个工作台一个文件节点，节点下面挂着它的 CSV 数据表），**右侧是整页 HTML**，上方一条插件自己的工具条（刷新 / 自动刷新开关 / 设置）。页面不是插件画出来的，而是 **dsh agent 直接生成并落盘到本机目录的 HTML**；插件只负责把它显示出来，并帮它读写旁边的 CSV 数据表。你既可以在页面上直接改数据，也可以用 Excel / 文本编辑器改同一份 CSV，两边最终落在同一份文件上。工作台页面的菜单、按钮、排版由 HTML 自己决定；**配色会跟随 dsh 的深色 / 浅色外观自动切换**，不需要你设置。

### 12.1 从头用起来

按顺序做这六步，**不用重启 dsh web**：

1. **设置里选数据目录**：打开 dsh 的「**设置 → Buddy 工作台 → 个人工作台**」，在「数据 → 数据目录」里填一个**绝对路径**（例如 `D:\我的数据\workbench-data` 或 `/home/me/workbench-data`），确认目录已存在、可写。留空表示清除配置，不改动就保持原值。CSV 数据表会放在这个目录下的 `<工作台 id>/<表名>.csv`。
2. **让 dsh 生成工作台 HTML**：直接用一句话让 dsh agent 帮你做一个工作台，例如「帮我做一个读书记录工作台」；也可以打 `@` 选一个现成模板（见 12.4）。dsh 会**按需加载内置技能 `workbench-creator`**（创建规则都在里面），并先问你一次偏好（工作台形态、增改表单怎么设、数据目录，共 3 个问题）——**不想选直接跳过按默认走**。生成好的 HTML 会直接落盘到 `$DSH_HOME/dsh-buddy-expert-hub/workbench/`（默认 `~/.dsh`，可用环境变量 `DSH_HOME` 覆盖），HTML 里内嵌了菜单与数据表声明。插件不提供上传 / 编辑 HTML 的界面 —— HTML 由 agent 落盘，插件只读。
3. **点「刷新」**：在工作台面板顶部的工具条上点「刷新」。列表每次都会重新扫一遍 HTML 目录，所以刚落盘的工作台立刻出现，**不需要重启宿主进程**。若某个 HTML 没出现，看列表给出的错误提示（见 12.3）。
4. **打开工作台**：在左侧文件树里点工作台名，右侧整页加载它的 HTML；点数据表名可以查看它对应的 CSV 文件。要调整左栏宽度，拖中间的分隔条即可；要改展示顺序，拖动文件节点到目标位置（或聚焦后按 `Alt+↑` / `Alt+↓`）。
5. **在页面上改数据 / 直接用 Excel 改 CSV**：两条路任选 —— 在页面里增删改行，页面通过桥把改动写回 CSV；或者关掉页面，用 Excel 打开 `<数据目录>/<工作台 id>/<表名>.csv` 直接编辑后保存。CSV 是 UTF-8，BOM、换行、带逗号或换行的单元格都按标准 CSV 处理。
6. **页面自动更新（可开关）**：工具条上的「自动刷新」打开时，外部（Excel / 编辑器 / 同步工具）改了 CSV 后，页面按设置里的检查间隔（默认 2000ms，可在 500–60000ms 之间调）自动收到最新数据并刷新；关掉这个开关就不再后台检查，需要时点一下工具条上的「刷新」。开关状态存在设置里，重启仍在。

> 数据表里的 `_id` 列由插件自动补齐，作为每一行的稳定标识，手工编辑 CSV 时不用（也不要）自己写这一列。

> **配置在哪改**：所有配置都在 dsh 的「**设置 → Buddy 工作台**」里（工作台工具条不再有齿轮），里面有数据目录、同步间隔、创建能力。设置里选好立刻生效，**不会丢正在填的表单**，也不会重载页面。
>
**左侧栏怎么调**：左栏和页面之间有一条细分隔条 —— 左右拖动改宽度（双击复位，聚焦后按 ← / → 也能微调），宽度会记住。工作台多了想换顺序，直接拖动左侧的文件节点到目标位置，或者聚焦节点后按 `Alt+↑` / `Alt+↓`，顺序会自动保存，下次打开还是这个顺序。

> **页面长什么样由 HTML 决定**：左侧是插件的工作台文件树（工作台 + 它下面的 CSV 数据表），右侧整页显示你的 HTML。页面里的菜单、按钮、配色、排版都在 HTML 里，插件不代画、也不提供风格开关 —— 想改样子直接让 dsh 改那个 HTML。

### 12.2 「数据表已被外部修改」冲突提示怎么办

如果你在页面上编辑的同时，这份 CSV 又被外部（Excel、网盘同步、另一个页面）改动了，保存时插件会发现你手里的版本已经不是磁盘上的最新版本 —— 这就是 **409 冲突**：插件**不会静默覆盖**外部改动，而是弹出「数据表已被外部修改」提示，并自动把磁盘上最新的数据重新载入页面。

弹窗给两个选择：

| 选择 | 结果 |
| --- | --- |
| **重试** | 以刚载入的最新数据为基准，把你这一次的改动重新合并写回；按字段名对齐列合并，新列留空、已有的行全部保留 |
| **放弃** | 丢掉你这一次还没保存的改动，页面停留在已载入的最新数据上 |

建议：先把外部改动看一眼，再点「重试」；若外部改动才是你要保留的版本，点「放弃」即可。冲突只在**同时改同一份 CSV** 时出现，单人顺序编辑不会遇到。插件的写入是进程内串行 + 原子替换（临时文件 → 重命名），不做跨进程 / 跨机器的分布式锁，所以多台机器同时写同一个目录仍要靠你自己的同步策略。

### 12.3 常见问题

**Q：设置里保存数据目录时提示「不可写」/ 校验不通过？**
填的必须是**已存在的绝对路径**，且插件进程对它可写（不是只读目录、不是文件、权限足够）。相对路径一律不接受；留空是清除配置，不是「随便放哪」。换一个自己有写权限的目录再保存；Windows 上带中文 / 空格的路径是支持的，照原样填绝对路径即可。

**Q：我放的 HTML 没出现在列表里 / 列表里有错误提示？**
单个 HTML 的菜单声明非法只会**降级跳过这一个**，不会影响别的工作台；列表里的错误提示会写明是哪个文件、什么原因。常见原因：`id` 不是小写字母 / 数字 / 连字符或超过 64 字符、`name` 为空、`version` 不是数字、`tables[].file` 带了路径或不是 `.csv`、JSON 本身写坏了，或 JSON 文本里出现了没转义的 `</script>`（应写成 `\u003c/script\u003e`）。照提示修好 HTML 再点「刷新」即可，不用重启。

**Q：改了 CSV 页面却不更新？**
依次检查：① 数据目录是不是设置里填的那个、CSV 是不是在 `<工作台 id>/<表名>.csv` 这个位置；② 轮询间隔是不是被调得很大（默认 2000ms，上限 60000ms）；③ 页面是不是还停在冲突提示上（先处理 12.2 的弹窗）；④ 保存时是不是被编辑器改成了非 UTF-8 编码或改坏了 CSV 结构。确认无误后点一下「刷新」或重新打开工作台。

**Q：用 Excel / 编辑器改完 CSV，页面里中文变成乱码？**
CSV 只支持 **UTF-8**。用 Excel 另存时选「CSV UTF-8（逗号分隔）」，用文本编辑器保存时把编码设成 UTF-8（可带 BOM，插件会自动剥掉）。不要用 ANSI / GBK / UTF-16 保存，也不要在字段里留下不配对的引号 —— 引号、逗号、字段内换行会按标准 CSV 规则处理，写成 `""` 表示一个字面引号。

**Q：为什么对话框里看不到创建规则了？**
这是 v2 的刻意设计：菜单声明、CSV / HTML 落盘路径、读写桥、409 冲突处理这些**完整创建规则已经放进内置技能 `workbench-creator`**，由 dsh agent 按需加载（同一会话只加载一次）；会话里只保留一段极短的常驻索引做能力发现，打 `@` 选模板后对话框只显示一个短 chip + 一句技能引用，**规则文本不进对话框**，所以对话保持干净，也不会每次生成都重新解析一遍规则。想看规则可以打开内置技能正文，或照着 `docs/workbench-example.html` 写自己的页面。

### 12.4 用 @ 指令一句话生成工作台

除了 12.1 里「自己写一句话让 dsh 生成」，还可以直接用输入框里的 `@` 指令，挑一个现成模板让 dsh 照着做，**同样不用重启 dsh web**：

1. **在输入框打 `@`**：会出现「个人工作台」分组，里面有 5 个模板 —— 读书记录、任务看板、家庭开支、健身打卡、自定义空白工作台。可以接着打字按名字筛，例如 `@读书`。
2. **选一个模板**：插件不会自己画页面，也**不会往输入框里塞一大段提示语** —— 对话框里只出现一个短 chip（如「个人工作台 · 读书记录」）和一句很短的技能引用；dsh 会**按需加载内置技能 `workbench-creator`** 拿到完整创建规则。菜单声明、CSV 与 HTML 的落盘位置、读写桥说明都在技能里，不占对话框。
3. **补一句自己的场景描述**（可选）：在 chip 后面补上你想要的样子，例如「再加一个按月份统计的图表」「字段里加一个标签列」，让 dsh 生成得更贴合你的用法。
4. **发送**：dsh agent 会按技能里的规则生成 HTML，并直接落盘到本机的工作台目录（首次创建会先问一次偏好，共 5 个问题，不想选直接跳过按默认走）。插件只负责显示，不提供上传 / 编辑 HTML 的界面。
5. **点「刷新」打开**：点工具条上的「刷新」，刚生成的工作台立刻出现，打开就能用。列表每次都会重扫目录，所以不需要重启宿主进程。

**想换数据目录**：默认用的是「设置 → Buddy 工作台 → 个人工作台 → 数据目录」里填的路径。有两种改法：

- 到独立「工作台设置」里直接改这个路径，保存即可；
- 或者在 `@` 后面把绝对路径一起带上，例如 `@读书 D:\我的数据\workbench-data`，Linux / macOS 写成 `@读书 /home/me/workbench-data`。路径放在关键词后面，允许带空格。发送消息时插件会自动把这个目录同步进设置，保证 dsh 落盘的位置和页面读写的位置是同一个；同步结果改用 toast 提示（成功 / 失败），如果同步没成功，toast 会提示先到「工作台设置」手动改成该路径，**不会阻断发送**，也不会悄悄把数据写到别处。

**如果 `@` 在宿主里被占用**：插件会退一步尝试 `@workbench` 这个前缀；要是两个都被宿主拒绝，插件会在浏览器控制台给出一条中文告警，这时 `@` 指令暂时用不了，但 `/` 技能指令和面板里的「个人工作台」都照常可用。你也可以直接按 12.1 的步骤，用一句普通的话让 dsh 生成工作台。

> `@` 菜单里只会出现工作台模板，不会冒出专家 / 技能 / 连接器候选；那些仍然从输入框工具栏的专家按钮选择。左侧栏新增了一个「个人工作台」入口，与「专家·技能·连接器」并列、排在它下方，点它直接打开独立的工作台面板。

## 13. 插件升级与介绍

### 13.1 在线升级

入口：**设置 → Buddy 工作台 → 插件升级**。

1. 点「**检查更新**」，会显示当前版本与 npm 上的最新版本；
2. 有新版本时出现「**立即升级到 x.y.z**」：下载安装包 → 校验 sha512 → 备份当前版本 → 覆盖文件，任一步失败会自动回滚到原版本；
3. 升级完成后**重启 dsh** 才会加载新代码；
4. 下方「最近升级」会记录每次的成功/失败与原因。

> Windows 上如果覆盖正在运行的文件被系统占用（EBUSY），升级会回滚并提示：此时用
> `dsh plugin --profile <你的 profile> add dsh-buddy-expert-hub@<版本>` 重装即可。

### 13.2 介绍弹窗

首次安装或版本更新后，启动 dsh 会弹出 4 页介绍（概览 / 资源 / 工作台 / 升级与反馈）。点「开始使用」后不再出现；想重看：**设置 → Buddy 工作台 → 关于与反馈 → 再看一次插件介绍**。

### 13.3 点 Star

同一页「关于与反馈」里有「**去 GitHub 点 Star**」，点开仓库后点右上角 Star 即可；问题与建议走旁边的「反馈问题」（Issues）。
