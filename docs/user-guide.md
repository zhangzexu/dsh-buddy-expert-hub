## 1. 安装与卸载

### 安装

```bash
# 开发态：从本地目录安装
dsh plugin --profile web add D:\path\to\dsh-buddy-expert-hub

# 正式：从 npm 安装
dsh plugin --profile web add dsh-buddy-expert-hub
```

安装后**重启 / 刷新 dsh web**，左侧边栏出现「专家·技能·连接器」图标即表示加载成功。

> 连接器的「连接」阶段会写入宿主 `cordis.patch.yml`，**写入后需要重启 dsh web** 才生效；插件无法重启自己所在的宿主进程。

### 卸载

```bash
dsh plugin --profile web remove dsh-buddy-expert-hub
```

卸载**不会**删除数据：`~/.dsh/ntd-resource`、`~/.dsh/dsh-buddy-expert-hub/`、`~/.dsh/experts/`、`~/.dsh/skills/` 都会保留。需要彻底清理时手动删除对应目录（删之前请先备份自己导入的专家和技能）。

## 2. 界面总览

点左侧栏「专家·技能·连接器」进入面板：

| 区域 | 作用 |
| --- | --- |
| 顶部四个标签页 | 专家 / 专家团 / 技能 / 连接器，徽标显示各自总数 |
| 工具栏左侧 | 「全部 / 已安装 / 云端」三视图按钮 |
| 工具栏右侧 | 一个 `+` 按钮，四个页各自含义不同（见第 4 节） |
| 搜索框 | 250ms 防抖；**每个标签页各保留自己的关键词** |
| 卡片 / 列表行 | 点击后右侧滑出详情抽屉，窄屏自动全屏；`Esc`、右上 ✕、点遮罩都能关 |
| 右上「刷新」 | 触发一次资源仓库同步；数据源是本机目录时改为重读目录，不联网 |

### 三视图的语义

| 视图 | 含义 |
| --- | --- |
| 全部 | 当前列表全量 |
| 已安装 | 本机已导入 / 已安装的条目 |
| 云端 | **按资源类型区分**：专家 / 专家团 = 资源仓库来源（排除本地导入）；技能 = **SkillHub 云端商店**；连接器 = `origin=cloud` |

补充：

- 技能页有两个子分组「仓库技能 / SkillHub 商店」，与工具栏视图**双向同步**：点子分组会切视图，点视图也会高亮子分组，不会出现两个视图渲染同一个列表。
- 连接器的「已安装」视图下多一行来源筛选：**全部 / 本地自定义 / 云端下载**，可继续细分。
- 空态会按当前视图给出下一步动作；「已安装」为空时引导点对应 `+` 按钮。
- 四个页的工具栏由同一个组件渲染，位置、样式、按钮顺序完全一致；`+` 按钮没有 `title` 悬浮提示，只有 `aria-label`。

### 列表细节

- 专家 / 专家团详情底部有「导入」按钮，导入后变成「已导入 ✓」并禁用；详情右上「导出」可生成单条目包。
- 已导入的专家在列表**置顶**，卡片带「本地」标识。
- 技能列表每页 60 条，滚动到底部或点「加载更多」继续加载。

## 3. 四个标签页怎么用

### 专家 / 专家团

浏览资源仓库里的条目 → 点卡片看详情（正文截断 2000 字）→ 点「导入」。

导入会把条目转换成 **dsh 原生专家格式**落到 `~/.dsh/experts/<id>/`，导入后即可在输入框的专家按钮里选用。同 id 已存在时不会覆盖，返回「已导入」。

### 技能

三个来源：

| 来源 | 说明 | 怎么用 |
| --- | --- | --- |
| 仓库技能 | 资源仓库 `skills/<集合>/.../SKILL.md` | 点卡片 `+` 或「添加技能」安装到 `~/.dsh/skills/` |
| SkillHub 商店 | 云端商店，切到「云端」视图 | 按分类浏览、搜索、安装；商店地址可在设置里改 |
| 内置技能 | 插件包自带，见第 8 节 | 设置里一个开关，装完在列表里不可见 |

技能引用要求**已安装且开启**：未安装会提示先点 `+`；已关闭会提示到「已安装」里开启，不再生成降级指令名。

#### 中文名、版本号与图标

资源仓库的技能目录里可能带两个可选文件，插件会自动识别，不需要你做任何配置：

| 文件 | 效果 |
| --- | --- |
| `_skillhub_meta.json` | `name`（中文名）替换列表 / 详情 / 选择器里显示的名称；`version` 在名称右侧显示 `vX.Y.Z` 徽标 |
| `_icon.png` / `.jpg` / `.svg` | 作为技能图标；没有或加载失败时回落到原来的彩色首字母方块 |

四处展示统一：技能列表卡、详情头图与「版本」统计、输入框专家按钮的选择器、「已安装」列表。搜索框也支持用中文名搜技能。

**不改变的东西**：`SKILL.md` 里的机器名、`/` 指令名、安装后的落地目录名都保持原样；装进 `~/.dsh/skills/` 时这两个文件会一起复制过去，所以已安装列表同样显示中文名、版本和图标。

> 维护者提示：资源仓库里部分目录带历史后缀 `__skillhub`（如 `academic-figures__skillhub`）。可用 `node scripts/strip-skillhub-suffix.mjs --root <skills 目录> [--apply]` 去掉（默认预演，`--apply` 才执行）。脚本**只改目录名、不改任何文件内容**，且插件对改名前后的 id 都做了兼容，旧草稿里的引用不会失效。详见 `README.md`。

### 连接器

见第 6 节（流程比其它三类多一步）。

### 资源版本更新与删除（3.1）

点开任意条目的**详情抽屉**，右上角会出现两个操作按钮（按状态显示）：

| 按钮 | 什么时候出现 | 行为 |
| --- | --- | --- |
| **更新** | 资源库里的版本比本地已安装版本更高时 | 覆盖安装到最新版：先删本地旧目录，再从资源库重新安装。更新完按钮自动消失 |
| **删除** | 这一份是插件自己装到本地的 | 删除本地安装，**不影响资源库**，随时可以再装回来。点之前会**二次确认** |

说明：

- **版本从哪来**：专家 / 专家团读清单里的 `version`，技能读 `_skillhub_meta.json`。本地版本取**安装当时记录下来的快照**，不会跟着资源库一起变——否则版本比较永远相等，更新按钮就永远不会出现。
- **连接器没有版本字段**，所以不显示「更新」，只显示「删除」（复用连接器原有的卸载逻辑）。
- **手工放到本地目录的条目不会被自动更新 / 删除**：只有插件装的（带安装标记或有安装记录）才显示这两个按钮，避免误删你自己的文件。手工条目要清理请自己删目录。
- 更新 / 删除成功后，四类列表会自动刷新，不需要手动点刷新。

## 4. 文件夹导入（+ 按钮）

专家 / 专家团 / 技能三个标签页的 `+` 按钮打开同一个「文件夹导入」弹窗，只是类型不同；连接器的 `+` 是手填 MCP 配置的表单，不走文件夹导入：

| 标签页 | 按钮 | 类型 |
| --- | --- | --- |
| 专家 | 导入专家 | `expert` |
| 专家团 | 导入专家团 | `team` |
| 技能 | 添加技能 | `skill` |
| 连接器 | 新增连接器 | 弹窗里手填 MCP 配置（不走文件夹导入） |

### 各类目录必需的校验文件

| 类型 | 目录根下必需 | 可选 / 兼容 |
| --- | --- | --- |
| 技能 | `SKILL.md`（frontmatter 建议写 `name`，解析不出用目录名兜底） | `README.md` 及其它资源 |
| 专家 | `expert.yml`（至少 `id` / `display_name`）+ `role.md` | 或 `.buddy-hub-plugin/plugin.json`（旧名 `.codebuddy-plugin` 也认；含 `name` / `displayName`），按兼容格式转换 |
| 专家团 | `expert.yml` + `role.md` + `team.json`（含 `teamInfo` 或 `members`） | 或 `plugin.json` 带团队信息（`expertType=team`），导入时生成 `team.json` |

校验失败会**逐条列出缺哪些文件**，后端是权威校验方，前端只做同规则轻量预检。

### 两种模式

1. **单条目**：先把所选目录整体当一个条目校验，通过就只导入这一个；
2. **批量**：整体校验不通过时，把**一级子目录**各当一个条目分别校验（只看第一层，不递归），成功的导入、失败的逐条列出中文原因；全部失败时给出汇总（如「3 个子目录均校验失败」）。

### 限制与落盘位置

- 单文件 ≤ 2MB、最多 200 个文件、解码后总计 ≤ 20MB（前后端双重限制）；
- 已知文本扩展名按 UTF-8 读，图片等二进制按 base64；
- 拒绝 `..`、绝对路径、Windows 盘符、反斜杠路径、符号链接；
- 技能落 `~/.dsh/skills/<净化后的名字>/`，专家 / 专家团落 `~/.dsh/experts/<id>/`；
- **绝不覆盖已存在目录**：同名返回 `already: true`，你手工改过的内容原样不动。

## 5. 在对话里使用：专家按钮与 `/`

### 专家按钮（输入框工具栏）

点击后弹出的二级列表**只列本机已安装的条目**（服务端按 `installed=1` 过滤）：

| 分类 | 列入条件 |
| --- | --- |
| 专家 / 专家团 | 本地已导入的条目 |
| 技能 | `~/.dsh/skills/` 里真实存在的技能（含已关闭的，选中时提示「已关闭」）；**内置开关装的那一批不列** |
| 连接器 | 本地已定义 / 已安装的连接器 |

某一类一条都没有时，会给出中文说明和一个「打开面板安装」按钮，直接跳到侧栏面板。

> **换专家就在当前对话里换，chip 会立刻更新。** 之前试过「一个会话只注入一次、第二次强制新建会话」，但宿主只能 `create` 会话、没有自动切换当前会话的能力，新建的会话不会变成你正在看的那个，结果就是「选了专家却看不到 chip」。现已改回：删除或直接换专家时，插件移除旧专家注入的设定、再在当前会话注入新专家，输入框工具栏的常驻 chip 随之更新。针对「AI 还在按旧专家行事」的问题，注入的设定里会明确声明「本会话当前唯一有效身份」，要求忽略此前其它专家及其子智能体。面板里点专家卡片的「召唤」仍会另开新会话，不受影响。

> 面板四个 Tab 本身不受影响，仍是「全部 / 已安装 / 云端」三视图；`installed=1` 只作用于输入框选择器。

### `/` 技能指令

- 触发字符**只有 `/`**：输入 `/` 从「技能」分组里选已安装且开启的技能。
- **` @ ` 不再弹出连接器列表**。`@` 完全回归宿主原生的「文件或对话」候选；专家 / 专家团 / 技能 / 连接器这四类一律走专家按钮。
- 指令名取自 `/skills/installed` 返回的 `dir`（即 `SKILL.md` frontmatter `name` 净化后的宿主原生技能目录名），**不是**仓库里的相对路径 `skills/<集合>/<名字>`。
- 发送后用户消息里**只显示 `/技能名`**，不会把整篇 `SKILL.md` 塞进发送内容。宿主启动时会扫描 `~/.dsh/skills/<dir>/SKILL.md` 并按需加载，插件再内联一遍是重复且白白耗 token。
- 关闭态技能宿主扫描不到，自然也不会出现在 `/` 菜单里。

技能引用一共**三个入口**，发送后统一变成 `/技能名`、都不会内联正文：① 输入框 `/` 菜单（主路径）；② 列表页技能卡片的「引用」气泡；③ 工具栏的专家按钮里的「技能」分类。三者都会先查已安装记录，再插入结构化引用，由同一份 codec 展开。旧草稿里残留的旧格式引用会自动净化成合法指令名，不会报错。

> `/` 同时是宿主内置 slash-menu 的触发符。插件注册前会探测 `inputTriggers`；若被拒，先尝试 `/skill`，两者都失败会明确告警「宿主不允许 / 触发源」，**不会静默退回 `@` 菜单**。可在控制台用 `__expertHubDiag().skillTrigger` 查注册结果，`__expertHubDiag().atTrigger` 会写着 `@` 源已注销。

## 6. 连接器三步：发现 → 安装 → 连接

**安装只保存定义，连接才写宿主配置。** 这是最容易混淆的一点。

### 第 1 步：发现

| 来源 | 位置 | 卡片显示 |
| --- | --- | --- |
| 云端 | 资源仓库 `connectors/connectors.json`（单文件清单） | 未安装的显示 `+` 图标 |
| 本地 | `~/.dsh/dsh-buddy-expert-hub/connectors/<dir>/connector.json` | 「本地自定义」或「云端下载」来源徽标 |

同 id 时**本地定义优先**。云端清单里每一条都会进列表，连不了的显式标出来：`cli`、`sse`、地址含 `${VAR}` 占位符的条目标 `connectable: false`、置灰「不可连接」，不给安装 / 连接入口。

### 第 2 步：安装

- 云端卡片点 `+` → 把定义复制到本地 `connectors/<dir>/`；**不写 profile、不保存凭据**；
- 顶部「+ 新增连接器」可手填：名称、描述、传输方式（Streamable HTTP / stdio）、URL 或命令+参数+环境变量、请求头、必填参数名（留空则从 `${VAR}` 自动推断）；
- 已安装卡片显示 **× 卸载**：移除本地定义并断开连接登记，同时按具体 id 清掉所有会话里注入的上下文（`detachedSessions` 会回报清理了几个会话）。profile 里的条目不会自动删除。

### 第 3 步：连接

连接会把 `mcp-client` 配置片段写进宿主 `cordis.patch.yml`。写入后**需要重启 dsh web** 才生效。

> 地址含 `${VAR}` 占位符的条目在面板内没有任何连接入口（`/connectors/connect`、`/connectors/provision`、`/provision/preview` 都会 400），因为占位符不会被配置求值，写进去就是跑不起来的地址。要用这类连接器，需手动编辑宿主 `cordis.patch.yml` 把占位符换成真实值。

## 7. 设置详解

所有配置都在 **设置 → Buddy 工作台**，左侧一行横向分区，共 7 个：**远程配置 / 资源仓库 / 个人工作台 / 在线资料库 / 智聊 / 插件升级 / 关于与反馈**。

其中「远程配置」可用一份 JSON 统一覆盖下面各分区的参数，单独说明见[第 13 章](#13-远程配置一份-json-统一下发设置)。「资源仓库地址」在填远程 git 地址时会多出一个分支子项。

### 7.1 资源仓库地址

默认远程资源仓库：`https://gitcode.com/zzx_2446/dsh-buddy-expert-hub-resource.git`

可以填两种：

| 类型 | 写法 | 行为 |
| --- | --- | --- |
| git 仓库 | `http://...`、`https://...` 或 `git@...`（不含空白 / `..`；`http://` 适用于内网自建 Git） | 配置分支后首次 `git clone --depth 1 --branch <分支>`，刷新执行 `git fetch --depth 1 origin <分支>` + `git reset --hard FETCH_HEAD`；未配置分支时不传分支参数，跟随远端 HEAD。分支可在设置里选，候选来自远端只读探测 |
| 本机目录 | **绝对路径** | 直接把这个目录当数据根读；不联网、不执行任何 git 命令，保存时校验目录结构，分支栏不显示 |

留空回到默认地址。**改成 git 地址是下次同步才生效**；切回 git 数据源时界面会提示「数据源已切换，点刷新以应用新数据源」，重启后仍会提示。

#### 7.1.1 资源仓库分支（仅 git 仓库）

地址填的是 `http://...` / `https://...` 或 `git@...` 时，设置弹窗会多出「资源仓库分支（可选）」一栏：

- 点「获取分支」从远端只读拉取分支列表（不克隆、不 checkout），选中即填入；私有仓库无权限或网络不可用时**仍可手动填写**分支名。
- 留空跟随**远端默认分支**（远端 HEAD）：此时 `clone` 不传 `--branch`、`fetch` 不指定 ref，由 git 自己决定检出哪个分支。默认资源仓库的远端 HEAD 是 `master` 而不是 `main`，所以这里不能写死 `main`。只接受纯分支名：字母、数字与 `.` `_` `-` `/`，不能以 `-` 或 `/` 开头，不接受 `refs/heads/...` 这类完整 ref，也不能含空格。
- 保存后**下次同步（点「刷新」）才生效**。只改分支、没改地址时同样会提示点刷新，因为索引内容可能随分支变化。
- 本机目录模式下这一栏不显示：该模式不执行任何 git 命令，也不会改动你目录里的工作树或当前分支。
- 若点「获取分支」提示「后端尚未加载新版本」：插件以 `link:` 方式装进 profile 时，后端 `lib/index.js` 只在 dsh 进程启动时 import 一次，**刷新浏览器只会更新前端资源**，必须重启 dsh web 进程才会加载新接口。此时仍可直接手动填写分支名，不影响保存。

数据根优先级：

1. 设置里配置的本机资源目录（需含 `experts/` / `skills/` / `connectors/` 至少其一）
2. 同步后缓存的 `~/.dsh/dsh-buddy-expert-hub/repo`
3. `~/.dsh/ntd-resource`（历史遗留的只读副本，通常只有 `experts/`）
4. 都没有 → 懒加载时自动克隆

> 如果只到第 3 级，专家立刻可用，但技能页会提示「技能数据尚未同步」并给「立即同步」按钮 —— 因为那份副本没有 `skills/`。

### 私有 Git 仓库（需要账号）

地址填的是远程 Git 仓库时，插件会用只读的匿名探测自动判断是不是私有仓库：需要账号才能访问时，设置弹窗多出「私有仓库凭据」一栏，填 **Git 用户名** 和 **访问令牌（PAT）** 即可。令牌用 AES-256-GCM 加密存在 `~/.dsh/dsh-buddy-expert-hub/credentials.enc`，不会写进 `state.json`、也不会回显；留空表示沿用已保存的令牌，点「清除」或「恢复默认」会删掉它。克隆、刷新、列分支时凭据走环境变量注入，不拼进 URL，也不会出现在命令行里。

> 内网 DNS 不通或探测超时时，插件**不会瞎猜**，可以手动勾选「这是私有仓库」来填写凭据。
> `git@` 开头的 SSH 地址用系统密钥，不需要在这里填账号。

## 8. 内置技能开关（重点）

设置弹窗里的「**启用内置技能**」开关（`role="switch"` + 原生 checkbox）：

### 开启会做什么

把插件包内随包发布的内置技能全部装进 `~/.dsh/skills/`：

| 来源 | Windows | Linux |
| --- | --- | --- |
| `builtin/<平台>/skills/*` 独立技能包 | 4 | 16 |
| `builtin/<平台>/builtin-plugins/<插件>/skills/*` 里自包含的 | 0 | 0 |
| **合计可装** | **4** | **16** |

平台映射：`win32 → builtin/windows`，其它（linux / darwin）→ `builtin/linux`。目录不存在或为空时按 0 个处理，开关仍可点、不报错。

插件来源的技能要过**九条自包含规则**：依赖 `mcp__*` 工具、`ToolSearch` 发现的工具、`editor_sdk` 本地服务、`allowed-tools:` 限制、`../Xxx` 上级路径、插件根 `core/ agents/ hooks/ shared/ dist/ bin/ prebuilds/`、正文含 `Plugin`/`插件`、引用了不在本目录内的 `scripts/...`，命中任一即排除（原因可在 `excluded` 里看）。原因是这类技能复制出来会变成「列表里看得见、一调用就报工具不存在」。顶层独立技能包**不做文本筛查**。Windows 的插件来源技能已按可用性核查清空（原来能装但依赖 WorkBuddy 客户端能力的那批，以及永不被安装的死资源，都已删除）；`workbuddy-office-routing` 现在只把本地 Office 文件任务导向 `wps-office-suite`。

### 装完为什么在界面上看不到

**这是刻意设计**：内置技能在「已安装」列表、`/pick?installed=1`、输入框专家按钮里全部隐藏；宿主启动时仍会原生扫描 `~/.dsh/skills` 正常加载它们。想确认装没装，看 `GET /builtin/skills` 的 `counts.installed`，或看磁盘上有没有带 `.builtin-skill.json` 的目录。

### 关闭会做什么（重要）

关闭 = **真删**，不是移到禁用目录：

- 扫描 `~/.dsh/skills/` 与 `~/.dsh/skills-disabled/`，把**带 `.builtin-skill.json` 标记**的目录 `rmSync` 递归删除（不进回收站）；
- **没有标记的目录一律不动** —— 你自己装的、导入的、手写的技能，哪怕同名也保留；
- 返回 `removed:[dir]` 列出实际删掉的目录。

⚠️ **如果你手动改过某个内置技能里的文件，关闭会把改动一起删掉。** 想保留，先复制到别处，或删掉那个目录里的 `.builtin-skill.json`（去标记后插件就把它当用户技能，不再删也不再覆盖）。

### 其它行为

| 项 | 说明 |
| --- | --- |
| 不覆盖同名 | 目标目录已存在但无标记 → 跳过并记入 `skipped`：「同名技能已存在，未覆盖」，你的文件逐字节不动 |
| 幂等 | 重复开启 = 覆盖升级（计入 `updated`）；重复关闭 = 删 0 个 |
| 重名处理 | 顶层先占目录名，插件来源撞名追加 `-2`、`-3` |
| 标记文件 | 每个装进去的目录内写 `.builtin-skill.json`（`from / platform / sourceDir / origin / plugin / installedAt`），**只有带标记才会被移除** |
| 启动不自动装 | 只在用户显式点开关时触发；开启后目录被手动删了，再关一次或再开一次即可恢复 |
| 复制限制 | 单文件 ≤ 2MB / 单技能 ≤ 40MB / ≤ 400 文件 / 跳过符号链接；超限的技能整体失败并记入 `skipped`，不影响其它技能 |

### 与 WorkBuddy 的关系（最容易误解）

dsh 和 WorkBuddy 是**两套独立运行时**，各读各的目录：

| 目录 | 谁加载 |
| --- | --- |
| `~/.dsh/skills/` | dsh |
| `~/.workbuddy/skills/` | WorkBuddy 客户端 |
| `~/.workbuddy/plugins/`（45 个插件及其自带技能） | WorkBuddy 客户端 |

所以：

- **在 dsh 里看不到 WorkBuddy 装的技能是正常的**，不是 bug，也不是没同步；
- 本插件**不再读取 WorkBuddy 的任何目录或注册表**，宿主装没装插件都不影响这 4 个技能的安装（旧版本曾按「宿主已装就跳过」，该判定已删除）；
- 想在 dsh 里用某个 WorkBuddy 技能，只能让它**真的落进 `~/.dsh/skills/`**：用第 4 节的「添加技能」指向那个目录、从 SkillHub 装、或打开内置技能开关。注意：依赖该插件运行时（`mcp__*`、`editor_sdk`）的技能搬过去也调不起来。

| 内容 | 位置 |
| --- | --- |
| 本地技能库（宿主原生扫描） | `~/.dsh/skills/<dir>/` |

## 10. 常见问题 FAQ

**Q1：装了插件但侧栏没有入口？**
确认 dsh 版本在 0.1.5 ~ 0.2.x 之间（见文首"适用运行时"）；安装后重启 / 刷新 dsh web；检查所用 profile 的 `package.json`（例如 `~/.dsh/profiles/desktop/package.json`）里 `dsh.profile.bundles` 是否包含 `dsh-buddy-expert-hub`，以及 `dependencies` 里是否有对应条目。

**Q1b：安装 / 启动时提示「插件版本与当前 Harness 不兼容」怎么办？**
本插件从 2.0.x 起已在 `package.json` 声明 `engines.dsh`（覆盖 0.1.5 到 0.2.x 的全部 rc/alpha），正常不会触发这条提示。若仍出现：

1. 确认装的是**声明了兼容范围的插件版本**（旧版没有该声明，高版本 dsh 会拦）；用 `dsh plugin --profile <profile> add dsh-buddy-expert-hub@latest` 装最新版。
2. 确认 dsh 版本未到 0.3.0（不在支持范围内）。
3. 确认用的是**新版市场索引**：索引里 `versions[].engines` 不能是空对象；若为空，重新托管仓库 `market/index.json` 或在 Discover 里刷新索引源。
4. 确实要在未声明兼容的版本上试用，可加一次性豁免（**风险自负**）：
   ```bash
   dsh plugin --profile <profile> allow-version dsh-buddy-expert-hub@<版本> --dsh-version <dsh版本> --accept-risk
   ```
   豁免只对"精确的包版本 + dsh 版本"这一对生效，不会永久放行。

**Q2：技能页提示「技能数据尚未同步」？**
当前数据根是 `~/.dsh/ntd-resource` 这类只有 `experts/` 的副本。点「立即同步」或右上「刷新」从资源仓库拉完整数据；若设置里填的是本机目录，检查该目录下有没有 `skills/`。

**Q3：为什么在 dsh 里看不到 WorkBuddy 装的技能？**
两套运行时、两套目录，互不相通（见第 8 节末）。把技能装进 `~/.dsh/skills/` 才会出现在 dsh。

**Q4：打开「启用内置技能」后，列表里怎么一个都没多？**
内置技能在界面刻意隐藏。看 `GET /builtin/skills` 的 `counts.installed`，或看 `~/.dsh/skills/` 里带 `.builtin-skill.json` 的目录数。

**Q5：关闭内置技能会把我自己装的技能删掉吗？**
不会。只删带 `.builtin-skill.json` 标记的目录；无标记目录一律保留，同名也不动。但会**删掉你对内置技能做过的手工修改**。

**Q6：输入 `@` 怎么不弹连接器了？**
这是新版设计。`@` 回归宿主原生的文件 / 对话候选，连接器、专家、专家团、技能都从输入框的**专家按钮**里选。

**Q7：选中技能后发出去只有 `/技能名`，提示词没带上？**
正常。宿主会按需加载 `~/.dsh/skills/<dir>/SKILL.md`，插件不再内联整篇正文，省 token 也避免发送框里一大段提示词。若技能完全没生效，检查它是否已安装且开启、目录里有没有 `SKILL.md`。

**Q8：连接器装了但用不了？**
「安装」只保存定义，还要点「连接」写入宿主 `mcp-client` 配置，并且**重启 dsh web**。另外 `cli` / `sse` / 含 `${VAR}` 占位符地址的连接器会被标「不可连接」，需要手工改 `cordis.patch.yml`。

**Q9：导入文件夹时提示缺文件 / 校验失败？**
对照第 4 节的必需文件表。专家要 `expert.yml` + `role.md`，专家团再加 `team.json`，技能要 `SKILL.md`。批量模式只看一级子目录，不递归。

**Q10：导入 / 安装时提示「同名技能已存在，未覆盖」？**
插件绝不覆盖已有目录。想用新版本，先在「已安装」里删掉旧的（或改名），再重试。

**Q11：内置插件里那些看起来很有用的技能（tencent-docs、weixinpay 等）为什么没装？**
它们依赖所属插件的运行时（MCP 工具、editor_sdk 等），单独复制过来一调用就报工具不存在，所以被九条规则排除。补齐 `mcps/` 也没用 —— 本插件只复制 `SKILL.md`，不注册任何 MCP server。

**Q12：为什么有的技能显示中文名和版本号、有的没有？图标怎么有的有有的没有？**
看技能目录里有没有 `_skillhub_meta.json`（中文名 + 版本）和 `_icon.*`（图标），两项都是可选的，缺哪个就不显示哪个，回落原来的英文名 / 彩色首字母块。中文名只是展示，不影响 `/` 指令名和安装目录名。

**Q13：资源仓库目录名里的 `__skillhub` 后缀要管吗？**
不用管，插件对改名前后都能读。想统一命名可以跑维护脚本（见第 3 节），脚本只改目录名、不改任何文件内容；改完点一次「刷新」重建索引即可。

## 12. 个人工作台

「个人工作台」是左侧栏的独立面板：**左侧是文件树**（每个工作台一个文件节点，节点下面挂着它的 CSV 数据表），**右侧是整页 HTML**，上方一条插件自己的工具条（刷新 / 自动刷新开关 / 设置）。页面不是插件画出来的，而是 **dsh agent 直接生成并落盘到本机目录的 HTML**；插件只负责把它显示出来，并帮它读写旁边的 CSV 数据表。你既可以在页面上直接改数据，也可以用 Excel / 文本编辑器改同一份 CSV，两边最终落在同一份文件上。工作台页面的菜单、按钮、排版、**配色**都由 HTML 自己决定：可以自带一套设计（大多数工作台都这样），也可以只用插件下发的宿主 token 跟随 dsh 深浅色。插件不会覆盖页面自己定义的颜色。

### 12.1 从头用起来

按顺序做这六步，**不用重启 dsh web**：

1. **数据目录（可跳过）**：HTML 页面和 CSV 数据表**共用一个数据目录** —— HTML 放目录根下、CSV 放 `<工作台 id>/` 子目录。**不配置也能直接用**：默认是 `~/.dsh/dsh-buddy-expert-hub/workbench/`（老用户的页面就在这里，零迁移）。想换目录时，到「**设置 → Buddy 工作台 → 个人工作台**」填一个已存在且可写的**绝对路径**（如 `D:\我的数据\workbench-data`）；插件会把旧目录里的 HTML 和 CSV **整体复制到新目录**，旧目录保留不删，失败会提示手动核对。留空回到默认目录。
2. **召唤专家搭工作台**：在专家列表里召唤「**在线工作台搭建师**」（`khub-workbench-builder`），告诉他要做什么。专家会先跟你确认四件事——页面名称、放在哪个目录、什么视觉风格、要哪几个功能模块——确认完才在**在线资料库**里建 HTML 页面和挂在它下面的 CSV 数据表。旧的 `@` 工作台模板和 `workbench-creator` 技能已经删除，不再使用；本地 `workbench/*.html` 落盘方案也仅作历史兼容，插件仍然能显示。
3. **点「刷新」**：在工作台面板顶部的工具条上点「刷新」。列表每次都会重新扫一遍数据目录，所以刚落盘的工作台立刻出现，**不需要重启宿主进程**。若某个 HTML 没出现，看列表给出的错误提示（见 12.3）。
4. **打开工作台**：在左侧文件树里点工作台名，右侧整页加载它的 HTML；点下面的 **CSV 数据表名，右侧会切换成可直接编辑的表格**（改完点「保存」，详见 12.6）。要调整左栏宽度，拖中间的分隔条即可；要改展示顺序，拖动文件节点到目标位置（或聚焦后按 `Alt+↑` / `Alt+↓`）。
5. **在页面上改数据 / 直接用 Excel 改 CSV**：两条路任选 —— 在页面里增删改行，页面通过桥把改动写回 CSV；或者关掉页面，用 Excel 打开 `<数据目录>/<工作台 id>/<表名>.csv` 直接编辑后保存。CSV 是 UTF-8，BOM、换行、带逗号或换行的单元格都按标准 CSV 处理。
6. **页面自动更新（可开关）**：工具条上的「自动刷新」打开时，外部（Excel / 编辑器 / 同步工具）改了 CSV 后，页面按设置里的检查间隔（默认 2000ms，可在 500–60000ms 之间调）自动收到最新数据并刷新；关掉这个开关就不再后台检查，需要时点一下工具条上的「刷新」。开关状态存在设置里，重启仍在。

> 数据表里的 `_id` 列由插件自动补齐，作为每一行的稳定标识，手工编辑 CSV 时不用（也不要）自己写这一列。

> **配置在哪改**：所有配置都在 dsh 的「**设置 → Buddy 工作台**」里（工作台工具条不再有齿轮），里面有数据目录、同步间隔、创建能力。设置里选好立刻生效，**不会丢正在填的表单**，也不会重载页面。
>
**左侧栏怎么调**：左栏和页面之间有一条细分隔条 —— 左右拖动改宽度（双击复位，聚焦后按 ← / → 也能微调），宽度会记住。**标题行最右边有一个收起按钮**，点一下把侧栏折成一条 32px 窄条（只留一个展开按钮），右侧页面自动占满；再点就展开，收起状态也会记住。工作台多了想换顺序，直接拖动左侧的文件节点到目标位置，或者聚焦节点后按 `Alt+↑` / `Alt+↓`，顺序会自动保存，下次打开还是这个顺序。

**在线模式下左侧栏是目录树**（空间 → 目录 → 工作台）：把工作台节点**拖到目录行**上就移进那个目录，也可以**右键工作台 →「移动到目录」**（适合触控板或目录多的时候）。目录行点一下可折叠 / 展开。移动只改变工作台页面挂在哪，数据表跟着页面走，不会丢数据。

> **页面长什么样由 HTML 决定**：左侧是插件的工作台文件树（工作台 + 它下面的 CSV 数据表），右侧整页显示你的 HTML。页面里的菜单、按钮、配色、排版都在 HTML 里，插件不代画、也不提供风格开关 —— 想改样子直接让 dsh 改那个 HTML。

### 12.2 「数据表已被外部修改」冲突提示怎么办

如果你在页面上编辑的同时，这份 CSV 又被外部（Excel、网盘同步、另一个页面）改动了，保存时插件会发现你手里的版本已经不是磁盘上的最新版本 —— 这就是 **409 冲突**：插件**不会静默覆盖**外部改动，而是弹出「数据表已被外部修改」提示，并自动把磁盘上最新的数据重新载入页面。

弹窗给两个选择：

| 选择 | 结果 |
| --- | --- |
| **重试** | 以刚载入的最新数据为基准，把你这一次的改动重新合并写回；按字段名对齐列合并，新列留空、已有的行全部保留 |
| **放弃** | 丢掉你这一次还没保存的改动，页面停留在已载入的最新数据上 |

建议：先把外部改动看一眼，再点「重试」；若外部改动才是你要保留的版本，点「放弃」即可。冲突只在**同时改同一份 CSV** 时出现，单人顺序编辑不会遇到。插件的写入是进程内串行 + 原子替换（临时文件 → 重命名），不做跨进程 / 跨机器的分布式锁，所以多台机器同时写同一个目录仍要靠你自己的同步策略。

### 12.3 常见问题

**Q：设置里保存数据目录时提示「不可写」/ 校验不通过？**
填的必须是**已存在的绝对路径**，且插件进程对它可写（不是只读目录、不是文件、权限足够）。相对路径一律不接受；留空是回到默认目录。换一个自己有写权限的目录再保存；Windows 上带中文 / 空格的路径是支持的，照原样填绝对路径即可。

**Q：改数据目录后原来的工作台和数据还在吗？**
在。保存新目录时插件会把旧目录里的 HTML（根目录）和 CSV（`<id>/` 子目录）**整体复制**到新目录，**旧目录保留不删**，所以两份都在、随时可核对。若迁移中途出错，会提示「迁移未完成」，新旧目录都原样留着，按提示手动复制即可。注意：新目录必须**事先建好且可写**，插件不会替你创建它。

**Q：让「在线工作台搭建师」搭工作台时，能改生成目录吗？**
**提问阶段能改**（四问里的「所在目录位置」可以换空间 / 换文件夹 / 自定义）；一旦复述确认单并确认、开始创建后，目录就**锁定**了 —— 创建过程中不会改目录、也不会把节点挪到别处重建（那会打断「HTML 节点 + 直接子 CSV」的识别关系，面板里就打不开）。想在别处再放一份，请另建一个工作台、重走四问。

**Q：我放的 HTML 没出现在列表里 / 列表里有错误提示？**
单个 HTML 的菜单声明非法只会**降级跳过这一个**，不会影响别的工作台；列表里的错误提示会写明是哪个文件、什么原因。常见原因：`id` 不是小写字母 / 数字 / 连字符或超过 64 字符、`name` 为空、`version` 不是数字、`tables[].file` 带了路径或不是 `.csv`、JSON 本身写坏了，或 JSON 文本里出现了没转义的 `</script>`（应写成 `\u003c/script\u003e`）。照提示修好 HTML 再点「刷新」即可，不用重启。

**Q：改了 CSV 页面却不更新？**
依次检查：① 数据目录是不是设置里填的那个、CSV 是不是在 `<工作台 id>/<表名>.csv` 这个位置；② 轮询间隔是不是被调得很大（默认 2000ms，上限 60000ms）；③ 页面是不是还停在冲突提示上（先处理 12.2 的弹窗）；④ 保存时是不是被编辑器改成了非 UTF-8 编码或改坏了 CSV 结构。确认无误后点一下「刷新」或重新打开工作台。

**Q：用 Excel / 编辑器改完 CSV，页面里中文变成乱码？**
CSV 只支持 **UTF-8**。用 Excel 另存时选「CSV UTF-8（逗号分隔）」，用文本编辑器保存时把编码设成 UTF-8（可带 BOM，插件会自动剥掉）。不要用 ANSI / GBK / UTF-16 保存，也不要在字段里留下不配对的引号 —— 引号、逗号、字段内换行会按标准 CSV 规则处理，写成 `""` 表示一个字面引号。

**Q：为什么输入框里打 `@` 找不到「个人工作台」模板了？**
`@` 工作台模板指令源和随包的 `workbench-creator` 技能都已删除。现在创建工作台的唯一入口是召唤「在线工作台搭建师」专家（`khub-workbench-builder`），它会在在线资料库里建页面和数据表，开搭前先确认名称、目录、风格和功能。

### 12.4 工作台是怎么创建的（历史）

早期的 `@` 工作台模板 + `workbench-creator` 技能方案**已整体删除**，输入框打 `@` 不再有「个人工作台」分组。
现在请召唤「在线工作台搭建师」专家（`khub-workbench-builder`）：它会先确认页面名称、目录位置、视觉风格和
功能模块四项，然后在在线资料库里建 HTML 页面 + CSV 数据表，页面在工作台面板左侧目录树里点开即用。

### 12.5 定时从外部更新数据（自动化任务）

工作台的页面跑在 iframe 里，**不能自己执行代码、也不能定时拉接口**。需要「每天自动更新」这类能力时，用 dsh 自动化任务跑你自己的采集脚本，把数据交给插件写进表。

**链路是这样**（脚本不需要任何密钥，也不需要联网到资料库）：

```
dsh 自动化任务（你设的频率）
  └─ 采集脚本（python / node，在你机器上跑）
       └─ 批次 JSON → 插件 ingest/inbox/
            ├─ 本地数据表 <数据目录>/<工作台 id>/<表名>.csv   ← 断网时页面读这个
            └─ 在线资料库（只推变化的行；失败自动排队，联网补推）
```

#### 三步用起来

1. **写批次文件**。脚本只要产出一个 JSON，写进 inbox 目录即可：

   ```json
   { "batchId": "stock-20261115-2100",
     "workbench": "khub-2", "table": "node-3.csv",
     "mode": "upsert", "primaryKey": ["日期", "代码"],
     "columns": ["日期", "代码", "收盘"],
     "rows": [["2026-11-15", "600519", "1680.5"]] }
   ```

   - `workbench` / `table` 在哪看：左侧文件树里点在线工作台，表名就是 `node-<id>.csv`；本地工作台是 `<文件>.csv`。
   - `batchId` 必须**每次不同**（带时间戳）。同 id 同内容会被当成重复投递跳过。
   - 不要写 `_id` 列，那是插件维护的行标识。

2. **inbox 路径**：工作台面板工具栏点「**同步**」→ 第一行就是完整路径，点「复制」直接粘进脚本。默认是 `~/.dsh/dsh-buddy-expert-hub/ingest/inbox`（Windows：`C://Users//你//.dsh//...`）。

3. **建 dsh 自动化任务**：让它按时间跑脚本。任务描述里写清脚本绝对路径、`workbench` 与 `table`、失败要报告不要重试。频率最细到**每小时**；更细就让脚本自己循环。

#### 三种写入模式

| mode | 语义 | 适合 |
| --- | --- | --- |
| `upsert`（默认） | 按 `primaryKey` 找同一行，**只覆盖 `columns` 里声明的列**，你在页面上手工加的其它列不会被动 | 行情、日报、指标这类反复更新的数据 |
| `append` | 只追加；带 `primaryKey` 时先按主键去重，重跑不会写两遍 | 日志、流水、消息 |
| `replace` | 批次就是全表（列也以批次为准） | 数据源本身是整表快照 |

**主键尽量用单列**（订单号、手机号、日期这类）。单列主键时插件直接把批次交给资料库的
「按主键 upsert」接口：服务端在文档锁内匹配，命中只改你声明的列、没命中追加，
**一次请求完成，不读整表**。两列以上的主键（例如「日期 + 代码」）也能用，但插件得自己算差异，
走的是「逐格改 + 追加行」，请求更多；变化特别多时才整表覆盖。

「同步」面板的「最近处理」里会写清这次走的是哪条路：`在线·按主键` / `在线·增量` /
`在线·整表` / `仅本地`。如果显示 `（降级）`，说明在线表里没有你写的那个主键列（可能改过列名），
插件已自动退回逐格路径，数据仍然会写进去。

#### 「同步」面板看什么

工具栏「同步」按钮上会带数字（待处理 + 待补推），点开能看到：

- **待处理**：inbox 里还没被处理的批次；点「立即处理」可以不用等 60 秒的自动扫描。
- **待补推**：数据已经写进本地，但当时在线连不上（断网 / 资料库没开），排队等补推。联网后点「立即处理」即补齐。
- **失败**：批次格式不对被拒，原文在 `ingest/failed/<批次>.error.txt`。
- **最近处理**：每条批次的新增行数、更新格数、走的是「仅本地 / 在线增量 / 在线整表」。

#### 断网与大数据

- 断网时批次照样成功：数据落本地镜像，页面照常显示；在线那一份排队，联网补推。
- 单批建议 ≤ 2000 行，硬上限 20 万行；更大的数据请脚本拆成多个批次（每批一个 `batchId`）。
  资料库的按主键 upsert 单次最多 5000 行，插件会自动分批，脚本不用管。
- 每次全量拉取的数据，可以只投「变化的行」：脚本先读本地镜像 CSV 比对，再提交差异，网络与合并成本都最小。

#### 常见问题

**数据没更新？** 按顺序看：①「同步」面板待处理数是否 > 0（> 0 说明脚本写进来了但还没处理，点「立即处理」）；②inbox 里有没有新文件（没有就是脚本没跑或路径写错，最常见）；③`ingest/failed/` 有没有同名 `.error.txt`；④`done/` 里有文件但页面没变 → 数据进去了，是页面 `columns` 和表头对不上。

**要不要把 API Key 写进脚本？** 不要。脚本只写本地文件，凭据在插件里（`credentials.enc`），脚本拿不到也不需要。

### 12.6 直接在面板里查看 / 编辑 CSV

不用打开 Excel，也不用进页面，**左侧文件树里的 CSV 数据表本身就可以点开编辑**：

1. 在左侧文件树里点某个 CSV 表名（例如「本周任务.csv」）；
2. 右侧从 HTML 页面切换成**表格视图**，每个单元格都能直接改；
3. 改完点顶部「**保存**」写回磁盘。

顶部按钮：

| 按钮 | 作用 |
| --- | --- |
| **保存** | 把当前改动写回 CSV。有未保存改动时才可点，旁边会显示「未保存」标记 |
| **重新加载** | 丢弃本地改动，重新从磁盘读最新内容 |
| **返回页面** | 退出表格，回到工作台的 HTML 页面 |

几个要点：

- **表头只读**：改列名会按新列名重组数据、丢掉原列，所以不允许直接改；要改表头请在 Excel 或 CSV 里改。
- **`_id` 列只读**：它是插件维护的行身份标识，显示的是短 ID，不要手动改。
- **改的是同一份文件**：面板里保存和页面里改、用 Excel 改，最终都是同一份 `<数据目录>/<工作台 id>/<表名>.csv`。
- **冲突保护**：如果保存时文件已被外部改过，会提示「文件已被外部修改，未保存」，点「重新加载」取最新内容再改（与 12.2 的 409 冲突是同一套机制）。

## 13. 远程配置（一份 JSON 统一下发设置）

**用途**：把设置页里的参数写成一份 JSON，填一个地址就能统一覆盖，适合多台机器 / 团队批量配置，不用每台手填。

**位置**：**设置 → Buddy 工作台 → 远程配置**（第一个 tab）。

### 13.1 怎么用

1. 点「**备份配置**」拿到当前配置（带中文说明，注释加载时会自动忽略；密钥字段为空串占位）；
2. 按需修改内容，二选一：
   - 放到任意 **http(s)** 静态地址（内网静态服务 / 对象存储 / GitHub Pages 都行），把地址填进输入框点「**从 URL 加载**」；
   - 或直接点「**上传 JSON 文件**」选本地文件。
3. 加载成功即覆盖对应设置项（数据源地址这类**下次同步生效**），顶部显示「已启用」和来源；
4. 想撤销：点「**清除远程配置**」，恢复加载前的本地设置。

### 13.2 能覆盖哪些参数

只列设置页 UI 上可见的项；**留空字符串表示「不改动 / 用默认」**：

| 字段 | 说明 |
| --- | --- |
| `sourceUrl` | 资源仓库地址（git 或本机目录） |
| `sourceBranch` | 资源仓库分支；留空跟随远端默认分支 |
| `skillhubUrl` | SkillHub 地址，默认 `https://api.skillhub.cn` |
| `workbench.dataDir` | 个人工作台数据目录（本机绝对路径）；留空保留当前值，不覆盖 |
| `workbench.syncMs` | 工作台检查间隔，500–60000 毫秒 |
| `khub.baseUrl` | 在线资料库服务地址 |
| `khub.clientId` | 在线资料库客户端 ID |
| `khub.clientSecret` | 客户端密钥（写本地加密文件，见 13.3） |
| `khub.apiKey` | 用户 API Key（写本地加密文件） |
| `khub.enabled` | 在线优先开关 |
| `zhiliao.replyBaseUrl` | 智聊服务端地址 |
| `zhiliao.enabled` | 启用智聊 |
| `about.repoUrl` | 关于页 / 头部点 Star 的仓库地址 |
| `about.starUrl` | 点 Star 目标；留空跟随仓库地址 |
| `about.feedbackUrl` | 反馈问题地址；留空为「仓库地址 + `/issues`」 |

### 13.3 密钥怎么处理（重要）

- `khub.clientSecret` / `khub.apiKey` 支持远程下发，但**只写入本机加密文件 `credentials.enc`**，不会写进 `state.json`、也不会在任何接口回显。
- 空串表示「**不改动**」，不是删除本地密钥，避免误删。
- 远程 JSON 是明文 http 内容，**密钥会经过网络**，只对可信地址使用。
- 清除远程配置时，会从加密文件的备份键**读回加载前的原密钥**并还原。
- 智聊的 `webhookSecret` / `internalSecret` **不支持**远程下发（明文下发签名密钥风险过高）；「内置技能」开关也不支持（涉及实际安装/卸载技能）。

### 13.4 注意：远程配置是「快照式」的

加载时会抓一份当前设置作快照，清除时**整体回滚**到加载前。因此：

- 加载远程配置后再手动改的设置，点「清除远程配置」会被回滚到加载前状态；
- 想保留手动改动，请不要在远程配置生效期间依赖「清除」，而是直接上传新的 JSON。

### 13.5 常见问题

**Q：点了「从 URL 加载」提示拉取失败？**
检查地址是否 http(s)（不支持 file://、ftp://）、是否 15 秒内能响应、文件是否超过 2MB、返回的是不是合法 JSON。

**Q：加载成功但某个值没变？**
看提示里的「部分字段未生效」——该字段值非法（如分支名带空格、URL 格式不对）会被跳过并在警告里说明。空的 `sourceUrl` 也会被忽略（恢复默认要用「清除」）。

**Q：示例里的 `//` 注释会不会导致解析失败？**
不会。加载端会先剥离注释再解析（`https://` 里的 `//` 不会被误伤），所以下载示例改完可以直接上传。

## 14. 在线资料库与「资料库」面板

### 先配置一次

到 **设置 → Buddy 工作台 → 在线资料库** 填后端服务地址和用户 API Key（客户端 ID / 密钥可留空，
它们只用于「测试连接」校验有效性），点「测试连接」确认能列出空间，再「保存配置」。
**在线优先默认开启，保存后立即生效，不需要再点开关**；只有你想强制只用本机目录时才把它关掉。
密钥会被加密保存在本机，再次打开设置页时不会显示明文（输入框留空即表示不改动）。

### 工作台会发生什么变化

打开「设置 → Buddy 工作台 → 个人工作台」那侧的侧栏入口「个人工作台」，左侧文件树会变成
在线资料库里的 HTML 页面及其挂载的 CSV 数据表（例如「个人工作台 → 本周任务.csv」）。
页面照旧能直接改单元格，改动写回在线资料库；其它人在资料库里改了，插件也会按
「自动刷新」的间隔收到最新数据。

如果在线服务没启动、地址填错、密钥过期或网络断开，工作台会自动回落到本机 HTML 目录与
CSV 目录，功能不受影响 —— 本地只作为备用。**写入**是个例外：在线写入失败会明确报错，
不会悄悄写进本地，避免两边数据不一致。

### 「资料库」入口

侧栏还有一个独立的「资料库」入口。左侧按「我的资料 / 团队空间」列出空间，
右侧是目录和文档列表：

- 左侧是空间树：点箭头展开目录，点目录名看它下面的内容，点文件名直接打开。
  鼠标移到任意一行会出现「···」，点开是贴着该行弹出的下拉菜单：新建子项 / 重命名 / 收藏 / 分享 / 版本历史 / 移动到… / 删除。
  也可以**直接在该行上点右键**，同一份菜单会在光标位置弹出；靠近窗口右/下边缘时会自动翻到另一侧，不会超出面板。
- 「+ 新建」点开同样是贴按钮弹出的下拉菜单，可选 Markdown 文档、CSV 数据表、HTML 页面或新建文件夹。
  菜单贴在触发按钮旁边、点空白处或选中任意一项即收起，不会像弹窗那样挡住整个面板。
- **侧栏可以拖宽、也可以收起**：左侧栏与右侧列表之间的分隔条左右拖动即改宽度（180–460px，
  默认 262px），双击复位、聚焦后按 ← / → 微调；标题行右侧的按钮把侧栏折成 32px 窄条，
  再点展开。宽度与收起状态都记在本机，下次打开保持。
- **收藏**：左侧「收藏」可按收藏夹分组筛选；已收藏的节点在树里带星标。
- **共享**：左侧「共享」分「我发出的 / 收到的」，能复制链接、改只读/可写、取消分享。
- **分享单个文档**：在左侧该文件上点「···」或右键 →「分享」，可选只读或可写、有效期（小时）、访问密码，
  生成的是资料库分享页 `/s/{token}`。HTML 直链**不在这里**，见下一条。
- **HTML 直链（与「分享」分开）**：打开 HTML 文档后，顶栏「保存」左边的「直链」按钮；工作台面板里是「刷新」左边的「直链」按钮。
  弹窗分两区：
  - **实时直链** `/p/{token}/{nodeId}`：打开就是页面本身，数据实时来自资料库。每条链接下面有「允许访客编辑」开关 ——
    关（默认）是只读，访客的新增行 / 改单元格会失败；开则改成可写，访客的改动会写回资料库，链接等同于可写凭证。
    切换只改这条分享的权限，**token 不变，已经发出去的链接继续有效**；旁边会显示「长期有效 / 有效期至 … / 已过期」。
  - **当前页分享（静态快照）** `/p/{token}`：把此刻预览画面冻结成静态页，访客只能看，点不动、不能输入、不能读写数据，
    之后文档再改链接里的画面也不变。生成前先把预览调整到希望别人看到的样子。生成时插件会向预览 iframe 请求渲染后的 DOM，
    剥掉脚本 / 事件、固化表单值、禁用交互元素，后端再加 `script-src 'none'` 的 CSP 兜底。
  两者都支持复制、新窗口打开、取消（取消后链接立即失效）。
- **版本历史**：同一个菜单里的「历史版本」，能预览内容或回滚（回滚会产生一个新版本）。
- 分享 / 版本 / 收藏 / 重命名 / 删除这些**节点级操作只在左侧菜单里**，编辑器顶部不重复放按钮，
  顶部只留「返回 / 编辑·源码·预览 / 保存」这些针对当前内容本身的动作。
- **Markdown 编辑**：默认是 Word 那样直接排版（工具栏分：撤销重做 / 段落格式下拉 / 加粗斜体下划线删除线 / 行内代码 / 文字颜色与高亮 / 对齐 / 列表与缩进 / 引用与代码块 / 链接、插图、3×3 表格、清除格式），
  保存时自动转回 Markdown；也可以切「源码」或「预览」。
- **表格**：工具栏最右侧一组「行+ 行− 列+ 列− 删表」专门管表格 —— 把光标点进某个单元格再点，
  就在该行下面插一行 / 在该列右侧插一列；只剩一行或一列时删除会把整张表删掉（不留空表）。
  表格保存成 Markdown 的 `| a | b |` 语法，重新打开仍然是一张能继续编辑的表，不会退化成一行竖线文本。
- **拖列宽 / 行高**：鼠标压到单元格**右边缘**会变成左右箭头，按住左右拖就是改列宽；
  压到单元格**下边缘**变成上下箭头，按住上下拖就是改行高。表头右缘那条淡蓝竖线就是可拖的位置提示。
  最小列宽 36px、最小行高 26px，拖过头也不会变成一条抓不回来的线。
  宽高保存在 Markdown 里表格下面那行 `<!--khub-table:{"cols":[...],"rows":[...]}-->` 注释里
  （注释在其它 Markdown 渲染器里不可见），所以保存后重新打开、或者拖过列宽再加列删列都不会错位。
- 顶部搜索框搜当前空间；「最近」按访问记录排列。
- 空间 / 成员 / 权限等后台管理功能不在本插件范围内。
- 各类文档在插件里怎么用：

| 类型 | 能做什么 |
|---|---|
| 目录 | 点进去看下一级，面包屑可返回 |
| Markdown | 源码 / 分栏 / 预览三种模式，改完点保存 |
| CSV | 表格里逐格编辑，可加行加列，保存时带版本校验（别人先改过会提示刷新） |
| HTML | 直接看渲染后的页面，也能切到源码改；页面里挂的 CSV 一样能读写 |

**HTML 预览与工作台面板是两条独立链路**：资料库里点开 HTML 文档走 `/khub/html`，
工作台面板里打开的工作台走 `/workbench/html`。两者都会注入同一套 `window.KB` 适配器，
并各自把挂载的 CSV（前 200 行）**随页面一起内联**，所以首屏不依赖消息通道，打开就有数据；
刷新与编辑单元格则由父窗口的桥接监听器转发到 `/khub/csv`。
页面右下角若出现红色诊断框，第一行「适配器 vN · 内置数据 N 张表」可直接确认当前加载的版本与内联数据数量。
| 图片 | 直接看 |
| PDF / 其它文件 | 能内嵌的直接看，其它的点下载 |
| Word (.docx) | ONLYOFFICE 可用时自动启用版式级预览，有写权限可点「编辑」进入版式编辑；不可用时按段落编辑正文，点「保存为新版本」写回（版式、图片、表格结构不变） |
| Excel (.xlsx) | ONLYOFFICE 可用时自动启用版式级预览，有写权限可进入版式编辑；不可用时单元格网格编辑，可切工作表页签；公式、样式保留，保存为新版本 |
| PPT (.pptx) | ONLYOFFICE 可用时自动启用版式级预览，有写权限可进入版式编辑；不可用时逐页文本预览（只读）；要改内容请下载后用本地 Office 编辑再上传 |
| 旧格式 .doc/.xls/.ppt | 不支持，请下载后本地编辑 |

**Office 版式级预览 + 在线编辑（有写权限时）**：在线资料库启用 ONLYOFFICE 时，打开 Word / Excel / PPT
会自动启用只读版式级预览——插件服务端带 PAT 代取编辑器配置，返回一张插件自身同源的薄 HTML，
在里面加载 Document Server，不嵌入在线 SPA；在线未配置 / 不可用 / 加载失败时自动回退到上面的
内置轻量查看 / 编辑。服务端确认该节点有写权限后，顶部会出现「编辑」按钮，点它切到版式编辑态，
再点「返回预览」可回到只读。也可随时点「切换轻量视图」回退。

保存由 OnlyOffice 通过在线资料库的回调**异步完成**（版本自动递增），插件侧不阻塞、不伪造版本号；
编辑器回报保存后只刷新目录并给提示，关闭前请稍候。编辑模式有服务端权限门槛：
`canWrite` 不为 true 时不生成可写编辑器、不下发可写配置，页面给出「切回预览 / 切回轻量视图」。
PAT 与编辑器 token 只存在于服务端生成的 frame HTML 里，不会下发到面板。相关端点：

- `GET /khub/office/status`：能力探测，只回传非敏感字段（`provider / enabled / docServerUrl / backendUrl / jwtConfigured / wpsConfigured`）。
- `GET /khub/office/config?id=&mode=view|edit`：服务端代取 OnlyOffice 配置；`mode=edit` 需在线确认 `canWrite=true`，否则返回 403 `forbidden` 且不含 token。
- `GET /khub/office/frame?id=&mode=view|edit`：返回插件自身同源的薄 HTML，浏览器在其中 `new DocsAPI.DocEditor` 加载；`mode` 缺省为 `view`。frame 通过 `dshe:office:ready/saved/close/error/fallback` 与面板通信，postMessage 的 targetOrigin 收敛到页面自身 origin，面板只接受同源且来自该 iframe 的消息。

配色由工作台页面自己决定（可自带主题，也可跟随 dsh 深浅色），插件只负责把它显示出来。

## 15. 插件升级与介绍

### 15.1 在线升级

入口：**设置 → Buddy 工作台 → 插件升级**。

1. 点「**检查更新**」，会显示当前版本与 npm 上的最新版本；
2. 有新版本时出现「**立即升级到 x.y.z**」：下载安装包 → 校验 sha512 → 备份当前版本 → 覆盖文件，任一步失败会自动回滚到原版本；
3. 升级完成后**重启 dsh** 才会加载新代码；
4. 下方「最近升级」会记录每次的成功/失败与原因。

> Windows 上如果覆盖正在运行的文件被系统占用（EBUSY），升级会回滚并提示：此时用
> `dsh plugin --profile <你的 profile> add dsh-buddy-expert-hub@<版本>` 重装即可。

### 15.2 介绍弹窗

首次安装或版本更新后，启动 dsh 会弹出 4 页介绍（概览 / 资源 / 工作台 / 升级与反馈）。点「开始使用」后不再出现；想重看：**设置 → Buddy 工作台 → 关于与反馈 → 再看一次插件介绍**。

### 15.3 点 Star

同一页「关于与反馈」里有「**去 GitHub 点 Star**」，点开仓库后点右上角 Star 即可；问题与建议走旁边的「反馈问题」（Issues）。
