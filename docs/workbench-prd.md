**原始需求复述（逐条保留语义）**

1. 用「个人工作空间」搭建个人 / 团队工作台。
2. 普通 HTML 能做汇报、攻略、作品集、看板：**能看、能分享，但内容写死**；工作台 HTML = 普通页面里加入 CSV 数据表，**能存数据、能双向同步，改一次页面就自动更新**。
3. 两类场景要能选清楚：把资料**变好看**（汇报 / 复盘 / 攻略 / 作品集，数据不常变，一个 HTML 页面就够）vs 把资料**变能用**（个人工作台 / 客户跟进 / 任务看板 / 记账，过去得配数据库，现在 HTML 加一张 CSV 数据表就行）。
4. 上手方式：把「xxx」换成场景发给 dsh ——「请使用个人工作台的能力帮我制作一个「xxx」的个人工作台，需要实现数据在线存储和双向同步。工作台需包含以下功能：xxx」；示例：读书记录、健身打卡、家庭开支 —— 凡是还在用备忘录或 Excel 凑合的事。
5. 数据在线存储：数据存在 CSV 表里，**不写死在页面代码里**。
6. 双向同步：页面上改会写回数据表；数据表里改，页面也跟着变。
7. 之后想加字段、换配色、加筛选，**直接说一句就行**。
8. 数据存储**可选择本地目录**；**HTML 展示文件放在插件工作文件夹下**；**菜单由工作台按每个 HTML 提供**；**提供用户任务搭配菜单功能**；支持 **Win / Linux / macOS 三端 dsh** 使用。

## 1. 产品目标与范围边界

**产品目标（2 句）**

> 让用户用一句话让 dsh 生成一个「能持续录入、能自动更新」的本地工作台：页面负责好看与交互，CSV 负责存数据，插件负责生成菜单、托管 HTML 与打通双向同步。
> 把「还在用备忘录 / Excel 凑合」的个人事务，变成不需要数据库、不需要服务端、三端可用的单机应用。

**两类场景边界**

| 维度 | 静态展示页（**本增量不做**） | 数据驱动工作台（**本增量范围**） |
| --- | --- | --- |
| 典型用途 | 汇报、复盘、攻略、作品集 | 个人工作台、客户跟进、任务看板、记账、读书、健身打卡 |
| 数据 | 写死在 HTML 里 | 存放在独立 CSV 数据表 |
| 变更方式 | 要改内容得重新生成 HTML | 页面里直接编辑即写回 CSV；外部改 CSV，页面自动更新 |
| 核心优势 | 好看、**能看能分享**、单文件 | **能用**、可持续录入、数据可被 Excel 打开与迁移 |
| 生成物 | 1 个 HTML | HTML + CSV 表结构 + 菜单声明 |
| 本增量覆盖 | 否 | **是** |

> 用户原文「能看，能分享」是**静态页的对比优势**，不是本功能的承诺；本 PRD 只描述右列，不新建静态页生成器与分享链路。

## 3. 关键约定

### 3.1 名词

| 名词 | 含义 |
| --- | --- |
| 工作台 | 一个 HTML 文件 + 其声明的菜单 + 其对应的 1..N 张 CSV 表 |
| 菜单声明 | 每个 HTML 自带的一段结构化声明，描述工作台名称、图标、菜单项与所用数据表 / 字段 |
| HTML 目录 | 插件工作文件夹下**新建英文子目录**，只放插件生成 / 托管的 HTML |
| 数据目录 | 用户在设置里选择的本机目录，存放 CSV；属于用户资产，插件升级 / 重装不得覆盖 |

### 3.2 CSV 数据契约（产品层约定，非实现细节）

| 项 | 推荐默认 | 理由 / 验收要点 |
| --- | --- | --- |
| 表数量 | 1 个工作台默认 **1 张主表**；声明结构允许 N ≥ 1 张（多表列为 P1） | 贴合「加一张 CSV 表就行」的上手门槛，同时不堵死看板 / 记账的多表需求 |
| 存放 | 数据目录 / `<工作台 id>` / `<表名>.csv`；HTML 目录与数据目录分离 | 数据不因重装 / 重新生成 HTML 而丢失 |
| 表头 | 第 1 行为字段名，字段名是**稳定标识**（建议英文 snake_case），展示名写在字段声明里 | 改配色 / 改展示名不应导致数据列错位 |
| 字段声明 | 每个字段给出 `key / label / type / required / default`；`type` 取 `string / number / date / boolean / enum` | 页面据此渲染输入控件与校验；类型信息不能只藏在 CSV 里（CSV 本身无类型） |
| 值格式 | 日期 ISO `YYYY-MM-DD`；布尔 `true/false`；数字不带千分位与货币符号；`enum` 用声明中的选项值；空值留空 | 三端解析一致，Excel 打开可读 |
| 行标识 | 每行含一个稳定行标识列（如 `_id`，或等价机制） | 避免「外部插入一行 → 页面按行号改错行」 |
| 转义 | 含逗号 / 引号 / 换行的值用引号包裹，引号内双写转义（CSV 通行规则） | 备注字段长文本不破表 |
| 编码 | UTF-8；**读取兼容 UTF-8 BOM**；非 UTF-8 明确报错而非静默乱码 | Win 中文 Excel / 记事本常见 BOM 与 GBK |
| 换行 | 读取兼容 CRLF 与 LF；写出沿用该表首次创建时的风格，首次默认 LF | 避免每次保存产生整文件 diff |

### 3.3 双向同步：触发方式对比与建议

| 方式 | 实时性 | 三端一致性 | 代价 | 建议 |
| --- | --- | --- | --- | --- |
| **轮询**（定时比对修改时间 / 大小 / 内容摘要后重读全文） | 秒级（默认 2s，间隔可配） | **最好**，行为与平台无关 | 常驻空读 IO；大表有秒级延迟 | **P0 默认机制** |
| **原生文件监听** | 近实时 | **差**：三端事件语义不同；编辑器原子写会重复 / 丢事件；网络盘与同步盘常失效 | 零 npm 依赖下只能用原生能力，需逐平台兼容与降级 | **P1 仅作加速**：监听只负责「提示重读」，正确性仍由重读保证 |
| **手动刷新** | 用户点击即时 | 最好 | 不满足「自动更新」 | **P0 兜底**：始终保留刷新按钮 |

> **结论**：P0 = 轮询 + 手动刷新；P1 = 监听加速。任何情况下以「重新读取 CSV 全文」为唯一真相来源，不做增量事件合并。

### 3.4 「用户任务搭配菜单」——原文最模糊，给出解读

| 解读 | 含义 | 备注 |
| --- | --- | --- |
| **A（推荐）** | 菜单项 = 工作台对外提供的**可复用动作入口**（如「记一笔开支」「本月汇总」）；用户可把某个动作**绑定 / 收藏到当前 dsh 任务或会话**，形成「任务 ↔ 菜单」搭配，点击直接落到该工作台对应视图 | 与「提供用户任务搭配菜单功能」最贴合，可与已有会话输入槽位能力衔接 |
| B | 菜单按「用户任务场景」分组：一个 HTML 声明多个任务分组（读书 / 健身 / 记账），侧栏按分组展示 | 实为菜单分组，成本最低 |
| C | 菜单项携带**预设提示词**，点击即把一句话指令发给 dsh AI（如「把这条记录加进读书台账」），菜单 = AI 指令模板的快捷入口 | 与「一句话改工作台」的心智一致 |
| D | 仅指菜单可配置：用户自定义菜单项名称、排序、显隐及与 HTML 的对应关系 | 最保守 |

**需用户确认的点（Q2）**

- 「用户任务」是指 dsh 的**会话 / 任务对象**，还是泛指「用户想做的事（场景）」？
- 「搭配」是**绑定关系**（任务记住选了哪些菜单），还是仅**并列展示**？
- 菜单项点击后是**打开页面视图**、**执行页面内动作**，还是**发一句话给 AI**？
- 搭配关系是**每任务独立保存**还是全局一份？是否需要持久化？

> **产品侧建议**：先按 **A + C 的最小交集**实现 —— 菜单项可声明「显示名 + 视图定位 + 可选提示词」，支持把菜单项固定到当前会话 / 任务的快捷区；Q2 确认前不进入详细设计（需求池 WB-07 暂定 P1）。

| WB-13 | 原生文件监听加速 | P1 | 监听可用时缩短感知延迟；监听不可用 / 事件丢失时自动降级为轮询且数据仍正确；不得因监听异常导致页面卡死或数据错乱 |

| WB-15 | 三端兼容：路径 | P0 | Win（盘符 / 反斜杠 / 含空格与中文）、Linux、macOS 各自完成一次「选择目录 → 写 → 外部改 → 自动更新」全链路，无路径错误 |
| WB-16 | 三端兼容：换行与编码 | P0 | Win 下 CRLF + UTF-8 BOM 的 CSV 可正确读取并回写；Linux / macOS 下 LF 正常；非 UTF-8 文件给出明确错误提示，不出现乱码或错列 |
| WB-17 | 三端兼容：监听差异与同步盘 | P1 | 网络盘 / 同步盘（OneDrive、iCloud 等）目录下轮询仍正常工作；任一平台监听失效时自动降级并给出提示 |
| WB-18 | 「一句话加字段 / 换配色 / 加筛选」 | P0 | 这是 **AI 重新生成 / 编辑工作台 HTML 的工作流，不是运行时配置器**：用户一句话 → 重新产出 HTML（含表头、菜单声明、样式 / 筛选）→ 插件重新加载即生效；不做可视化拖拽配置器、主题系统或运行时字段编辑器 |
| WB-19 | 表结构变更时保留已有数据 | P0 | 新增字段 / 换配色 / 加筛选后，CSV 中已有行全部保留，新列留空；无需用户手工迁移或导出导入 |
| WB-20 | 空态与错误态 | P0 | 见第 5 节；每类异常均有明确文案与可操作下一步，无静默失败、无白屏 |
| WB-21 | CSV 本地版本备份与误改回滚 | P2 | 保留最近 N 次写入前的副本，用户可从设置中恢复；不引入云端同步 |
| WB-22 | 非 UTF-8 编码探测与转码提示 | P2 | 遇到 Win 中文 Excel 导出的 GBK 等编码时提示用户转码而非静默乱码 |

## 5. UI 设计稿（文字描述）

**侧栏入口**

- 工作台入口 = 面板内**第 4 个大块**，与既有专家 / 专家团 / 技能 / 连接器并列；**共用现有唯一侧栏图标**（`sidebar.panellist` 注册保持不变），**不新增宿主侧栏插槽条目**。
- 该大块内含**面板内二级菜单**，按「工作台 → 菜单项」两级树展示，数据来源为各 HTML 的菜单声明，插件不硬编码任何工作台名称；大块入口显示工作台数量徽标。
- 「侧栏右侧主区域承载 HTML」由**该大块内的 iframe** 实现，需足够展示宽度，**不得挤成窄列表**。
- **现状校正**：侧栏目前只有 **1 个**入口图标（`PanelIcon`），专家 / 专家团 / 技能 / 连接器是**面板内部的 Tab / 分组**，不是 4 个并列侧栏入口；不应按「4 个并列侧栏图标」建模。

**菜单结构**

- 一级：工作台（名称 + 图标，来自声明）；支持折叠。
- 二级：该工作台声明的菜单项（如「总览」「添加记录」「本月统计」）。
- 点击菜单项 → 页面区加载对应 HTML 并定位到该视图 / 动作；当前选中项高亮。
- 若 Q2 按推荐解读实现：菜单项旁提供「固定到当前任务」操作，被固定的项出现在会话快捷区。

**工作台页面区**

- 工作台 HTML 需要**足够宽度的展示区**承载表格 / 表单 / 图表，**不得挤成窄列表**；顶部工具条显示：工作台标题、**刷新按钮**、**最后同步时间**、当前数据目录（可点击跳到设置）。
- 页面内的表格 / 表单 / 图表由 HTML 自身渲染，插件只负责加载页面与提供数据读写通道，不接管页面布局。
- 外部改动生效时给出轻提示（如「数据表已更新」），不打断正在输入的表单。

**设置入口**

- 复用现有设置弹窗，新增「个人工作台」分区：
  - 本地数据目录（手输 / 浏览、当前路径、可读写校验结果）
  - 同步间隔（默认 2s）
  - 冲突处理策略（默认策略只读展示）
  - 「打开 HTML 目录」快捷入口
  - 本地版本备份开关 / 回滚入口（P2）

**空态**

- 无任何工作台：标题「还没有工作台」+ 一句话说明 + 示例提示词（把「xxx」换成读书记录 / 健身打卡 / 家庭开支）+「打开 HTML 目录」按钮。
- 已选数据目录但无数据文件：提示「该工作台还没有数据，添加第一条记录后会自动创建 CSV 表」。

**错误态**

| 情形 | 文案方向 | 可操作下一步 |
| --- | --- | --- |
| 数据目录不可读 / 不可写 | 明确指出路径与失败原因 | 重新选择目录 / 重试 |
| CSV 缺失或表头与声明不匹配 | 指出缺失的表与不一致字段 | 重新加载 / 打开数据目录 / 让 dsh 修复表结构 |
| 编码不支持、解析失败 | 指出文件与编码问题 | 转码后重试（P2 探测） |
| 外部与页面同时改（冲突） | 「数据表已在外部被修改，已重新加载，请确认后重试」 | 重试提交 / 放弃本次修改 |
| 菜单声明缺失或非法 | 指出具体 HTML 文件 | 跳过该工作台 / 以默认菜单展示 |
| 监听不可用（P1） | 「已切换为定时检查」 | 无需操作，可手动刷新 |
